# Codex（壁纸）专用启动器：P1 静态背景候选

本入口启动官方 Codex、核验实例归属后加入一层静态渐变，并提供即时停用。主聊天表面使用跟随主题的半透明读底，代码、差异、工具卡片和输入区保留局部实底。只接受本机已核对的 MSIX `26.1106.6628.0` 及对应原 EXE；更新后先用原入口，待复核版本再试。需要 Windows PowerShell 和支持 `--no-use-env-proxy` 的 Node.js 24（本机已具备）。不用管理员权限、不开机自启，不安装任何快捷方式。

## 什么时候点

挑一段没有 Codex 任务在跑、可以正常退出应用的空闲时间，建议预留 **10–15 分钟**。测试不是后台进行：你需要确认实际登录状态和一个已有聊天是否可用。当前工作中的 Codex 不用动；等你自己安排好时段再开始。

确认已保存工作，使用应用的「退出」完全退出（关窗口或最小化可能仍在运行）。**双击 [Codex-Wallpaper.cmd](Codex-Wallpaper.cmd)** 即显式尝试冷启动；运行中遇到任何 `ChatGPT.exe` 主进程时会停下。新版不匹配、启动失败或探针超时时也不会重试，不会自动关掉应用。

## 手动验收顺序

| 步骤       | 怎么做                                                                   | 看什么                                                                                                                                                             |
| ---------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 原版对照   | 正常退出后点 Windows 开始菜单里已注册的原 `ChatGPT` 入口。               | 原账号能打开一个你熟悉的已有聊天；再正常退出。                                                                                                                     |
| 专用入口   | 双击 `Codex-Wallpaper.cmd` 一次，等待结果。                              | 控制台 `Outcome: read-only-probe-passed` 和 `Wallpaper: enabled`；主界面出现静态渐变及右下角停用按钮；你自己确认原账号和同一个已有聊天可用。脚本无法替你验证登录。 |
| 复用与重开 | 保持该实例运行，再点一次专用入口；然后正常退出，再从专用入口冷启动一次。 | 重复点击显示已有实例且不产生第二个实例；再次冷启动同样通过探针并保持登录。P0b 的重复点击为无操作，不重连已经结束的探针。                                           |
| 撤销       | 正常退出专用入口打开的 Codex，再用原入口启动。                           | 原账号和聊天可用，状态检查显示无调试开关及主进程监听端口；专用启动器没有常驻进程。                                                                                 |

**一旦出现登录页、意外导航、未验证的端口或超时，就停止本轮。** 不在测试界面重新登录，不切换 profile，不连续重试。若应用已启动，按正常方式退出，再从原入口确认；脚本本身不会终止任何进程。普通的网络或登录问题也不能算成通过。

点击右下角“停用壁纸”后，背景节点和样式会立即移除；停用状态会在下一次专用入口启动时保留。当前实例内按 `Alt+Shift+W` 可以启用或停用壁纸。该停用只撤销界面层，不关闭启动参数开启的调试监听。

## 查看结果与撤销

启动前会核对日常数据目录是否已存在。Owl 报告的 Roaming 路径也可能对应同一个官方 MSIX 包的 `LocalCache\Roaming` 目录；启动器认可这两个位置，既不创建目录，也不把任何一个路径作为启动参数。如果两处都不存在，仍会在激活前停止。

启动尝试的报告会写到 `%LOCALAPPDATA%\CodexWallpaper\P0b`，控制台显示具体路径。只保存时间、版本、进程与端口号、路径是否匹配、只读探针结果和背景状态；不保存原始参数、登录数据或聊天内容。`read-only-probe-passed` 只代表技术探针通过，仍需完成账号、聊天和撤销对照。

启动期间若一次看到多个主进程候选，启动器会先等待，不连接 CDP。若 3 秒内恢复为唯一候选，会按原有包身份、进程身份、profile 和端口归属规则核验；持续有多个候选则报 `multiple-main-processes` 并停止。总体超时仍有歧义时报告 `root-ambiguity-at-timeout`。新报告的 `RootObservations` 记录候选 PID、父 PID、创建时间、是否匹配官方 EXE 及命令行是否可读，不记录原始命令行。它记录的是筛选候选，不能单独证明打开了几个窗口。

想确认是否还在运行，或确认撤销结果，可在本仓库根目录运行以下**状态检查**。它没有 `-Launch`，不会启动 Codex，也不会连接调试端口：

```powershell
powershell.exe -NoProfile -STA -File .\launcher\Start-CodexWallpaper.ps1
```

冷启动前预期 `Running` 为空；撤销后的普通实例预期 `DebugFlag: false`、`ListeningPorts: []`。若要复核某一次试验端口，可从报告取 `Port`，查看是否仍由该试验进程监听。探针只连接经归属核对的环回端口，但环回不等于鉴权。**探针结束后，端口仍可能在监听**；正常退出该实例才会关闭它。停止使用这个 `.cmd` 即可停用专用入口；无需变更原入口、原包或 profile。
