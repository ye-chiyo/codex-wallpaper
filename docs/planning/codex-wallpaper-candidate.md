# Codex 壁纸发布候选

本页记录 `codex/release-review` 的验收范围。候选面向 Windows 版 Codex 主界面，入口、安装和清理见 [启动器说明](../../launcher/README.md)。

- 实现提交 `751750414bc11316a58efd3fffc9732da758985b`。此后本分支的文档提交只更新验收说明。
- 上游基线为 GitHub `main` 的 `a70f6f16c1ea92ae813b02627c48cf45be57789b`。
- 启动器允许 x64 MSIX `26.1111.2228.0` 和 `26.1117.3838.0`，分别校验原 EXE SHA-256、应用登记、主进程与主界面。使用 `launcher/Codex-Wallpaper.cmd` 或自行编译的 GUI 桌面入口。

## 验证记录

### 自动化

在干净的 Windows 检出中，以 Node.js `24.16.0`、pnpm `11.25.0` 运行。检出路径含中文和空格。浏览器用例使用独立的 Edge 测试页面，启动器用例使用测试进程、临时目录和模拟 Codex 包身份。

```powershell
pnpm install --frozen-lockfile
pnpm test
powershell.exe -NoProfile -File .\\launcher\\desktop-entry.test.ps1
powershell.exe -NoProfile -File .\\launcher\\profile-preflight.test.ps1
powershell.exe -NoProfile -File .\\launcher\\startup-entry.test.ps1
powershell.exe -NoProfile -File .\\launcher\\startup-roots.test.ps1
```

结果为 Node **71/71**（无跳过）及 **4/4** 个 PowerShell 测试脚本通过。覆盖版本和主界面核验、重复启动、目标恢复、旧配置、导入切换、失败保留和停用清理。

另外检查了 launcher 下各 `.mjs` 的 `node --check`、各 `.ps1` 的 PowerShell 语法树、改动文件格式和基线差异。两个 CMD 入口使用含中文及空格的临时脚本验证参数转发和退出码。清理脚本以 `-WhatIf` 确认目标仅限项目自有目录。

### 真实 Codex

2026-11-21 对已安装的 `OpenAI.Codex` x64 `26.1117.3838.0` 只读核对。应用登记、原 EXE SHA-256 和预览使用的本地包图标均符合候选预期。状态入口识别出一个已运行、路径匹配的主进程。本次保留使用中的 Codex，实时会话未用于启动、注入、媒体操作或重置测试。

任务 12 仍待完成。2026-11-20 在较早的未提交候选上曾用 `26.1111.2228.0` 真实启动至 `wallpaper-ready`，其运行时和样式指纹前缀为 `4825681e` / `47a54154`。该次启动后主界面目标再次切换，宿主退出，随后由再次运行专用入口手动恢复。当前提交已用夹具验证目标短暂重叠后自动恢复，并覆盖持久化停用状态。真实连续恢复还需在当前提交重跑。

当时同进程已播放的前置 `moov` 视频热切首次真实动态帧 p95 为 **300.3 / 309.3 ms**，超过 **300 ms** 的门槛。历史结果没有原入口与专用入口的完整 T0–T7 对照，也未获得独立的 T5 壁纸首帧和 T6 首次动态帧启动样本。

### 用户视觉验收

当前候选等待用户在真实 Codex 窗口确认。重点包括聊天背景与边线、浏览器与变更侧栏、输入区、明暗主题、高 DPI、桌面预览交接，以及停用后恢复原界面的效果。

## 待完成的实机步骤

1. 记录 `git rev-parse HEAD`、Codex 包版本及测试条件。保存工作，完全退出 Codex。先从原入口冷启动并确认已有会话可用，记录对照启动数据。再次完全退出，从 CMD 专用入口冷启动，记录 `Outcome`、首帧、真实动态帧及输入和滚动可用时间。首次无缓存和有缓存分别观察，有缓存时额外检查 GUI 桌面入口。用状态入口验证只有一个预期主进程。
2. 在运行中再次调用专用入口。预期为 `dedicated-instance-reused`，主进程和界面只各有一份。用普通 Codex 实例重复一次，预期拒绝附加。用正常操作切换项目和聊天，若确实发生主界面目标替换，等待候选在 25 秒窗口内恢复原选择，再重复一次。每次确认壁纸、输入框和侧栏可用。若无实际目标替换，将该轮记为未覆盖。
3. 使用有权本地测试的图片、前置与尾置 `moov` 的 MP4、Scene 及离线 Web。以 `Alt+Shift+S` 打开设置，导入素材、调整参数、切换窗口并重开核对持久化。连续快速切换 A→B→C 和 A→B→A，再在切换中用 `Alt+Shift+W` 停用。观察 500 ms 内移除层与播放器，持续 30 秒无复活。检查缺失或不可解码素材是否保留当前画面或按类型降级。
4. 重测同进程前置、尾置 MP4 热切，每种布局至少 20 次。记录从点击到画面呈现且 `mediaTime` 持续前进的时间，报告 p95 和最大值，热切门槛分别为 300 ms 和 500 ms。启动对照记录触发（T0）、进程出现（T1）、窗口可见（T2）、目标核验（T3）、宿主就绪（T4）、壁纸可见（T5）、动态帧（T6）、输入滚动可用（T7）。原入口的壁纸专用阶段可记为不适用。冷启动至少各测 5 次，样本不足以计算 p95 时保留原始值、中位数和最大值。
5. 在可丢弃的验收配置中完成页内两次确认清理。持久化停用后完全退出，从专用入口重新启动，确认 `Alt+Shift+W` 可恢复，并能重新加载工坊素材。确认登录、注销、重启和重复触发时的 Startup 行为。测试后撤销临时登录入口及专用快捷方式并从原入口启动，核对项目监听随此前专用实例退出而关闭。
