# Codex 壁纸移植验收矩阵

日期：2026-11-10（Asia/Shanghai）。来源：requirements-alignment.md 的 Q1–Q16。状态：需求转写，尚未执行验证；具体样本、计量阈值与操作次数需在技术方案阶段确定。

## 结果分层

1. 接入可行性：真实 Codex 主界面可显示壁纸，现有操作正常，能撤销。独立网页或壁纸预览不能代替本层证据。
2. 基础验收：实际部署版本完成至少 8 小时连续使用测试及下列界面/生命周期检查。
3. 长期观察：基础验收后的候选版本完成 7 天日常观察，记录故障及恢复，才能评价长期稳定。

源代码、测试版本、已安装版本、当前运行版本必须分别记录。某层通过不代表后续层通过；修复后的版本变化对哪些证据有影响，应明确说明。

## 尚待技术验证解决的量化项

- 记录原始 Codex 与适配后在同一操作/素材下的 CPU、GPU、内存和响应表现，据本机测量提出预算，并在正式长时验收前确认。
- 明确多窗口资源开销、播放器/辅助程序数量与持续内存增长检查方式。
- 明确故障恢复时间、恢复尝试边界、状态提示与诊断信息，避免无休止重试。
- 确定每类代表素材及降级结果，记录采用的上游版本和渲染器版本。

这些是需要落实的验证任务，不是已经测得的数字或已确认的具体实现。
