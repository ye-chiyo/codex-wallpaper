## 可行性判断

可以把「一次显式带参的启动」作为具体候选。新增一个独立的用户快捷方式，例如「Codex（壁纸）」，由它激活同一个已注册的官方 MSIX；原开始菜单、任务栏和协议入口保留。用户选择专用入口时才尝试接入，普通原入口冷启动维持原样。

[Windows 激活 API](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateapplication) 允许调用方传入参数。此前的[本机 P0a](codex-p0a-validation.md)证明旧版原 EXE 可在隔离 profile 中响应主界面 CDP；[P0b](codex-p0b-validation.md)证明热激活不能给已运行的日常实例补开 CDP。当前 `26.1106.6628.0` 的原 AUMID 仍为 `OpenAI.Codex_2p2nqsd0c76g0!App`，现有工作主进程仍为 `26152`（创建时间 `1794457893.48387`），无调试参数或进程树 TCP 监听。crashpad 子进程参数仍显示 `%APPDATA%\Codex\web\Codex`；仅检查参数，未读取登录文件或聊天。

还缺两个关键实测：**带参冷激活能否让当前 Owl 打开 CDP，以及打开 CDP 时能否仍使用现有已登录 profile。** [Chrome 的默认数据目录调试限制](https://developer.chrome.com/blog/remote-debugging-port)不能直接当成 Owl 的已知行为；如果当前 Owl 确实拒绝在日常 profile 中启用调试，按失败处理，不通过新目录、复制会话数据或修改安全设置绕过。

## 启动器的具体行为

1. **启动前核对。** 只在同一 Windows 用户下运行，无管理员权限或后台预启动。解析当前官方包和 AUMID，核对测试覆盖的版本及启动文件；版本变化时暂停适配。识别现有 Codex 主实例，避免快速重复点击造成第二次启动。只读验收版遇到任何已有实例均无操作；不关闭它、不向它补传参数、不自动重试，也不重新连接已结束的探针。
2. **首选启动。** 调用同一个官方 AUMID，仅为此次冷启动传入环回地址与本次端口的 CDP 参数。让原应用按自身规则决定数据目录：不传 `--user-data-dir`，不设置或改写 `CODEX_ELECTRON_USER_DATA_PATH`、`CODEX_HOME` 或 `BUILD_FLAVOR`，不迁移或读取凭据、存储和聊天数据库。不添加开机项或改原快捷方式。
3. **确认连接。** 在有限等待时间内查找新主进程，核对 PID、创建时间、已注册包身份、监听归属与地址；激活 API 的返回 PID 本身不作为证明。只接受该实例的本机环回监听和预期主界面 `app://-/index.html`。P0b 只执行 `Page.getFrameTree` 读操作并记录结果。不连接其他端口或内置浏览器标签，不开放网卡地址或放宽调试来源限制。环回端口仍允许本机进程接触，随机端口不是鉴权；这项暴露必须在将来决定是否日用时单独评估。
4. **失败处理。** 激活参数若被丢弃、重解释为协议、端口没开、监听归属不符、界面不符或出现登录页，停止接入。若 Codex 已启动，保留实例让用户自行处理，不自动退出重开。仅在证据显示问题是 AUMID 未传递参数、并确认直启仍能使用原包身份和同一 profile 的条件下，才把精确包内 EXE 的原生带参启动作为一次单独排期的对照。它不是自动回退，更不能为绕过默认 profile 限制而改变数据路径。

## 冷启动验收

以下步骤只在用户保存工作并选择验证时段后执行；完全退出以主进程结束为准，关窗口或最小化不算。

| 步骤          | 操作                                                                                       | 通过条件                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 1. 对照       | 用原入口冷启动；用户确认同一账号，并打开一个已知的已有聊天，再正常退出。                   | 已登录且聊天可用，记录包身份、版本、原入口和默认 profile 路径元数据。                              |
| 2. 专用入口   | 仅点击专用入口一次，观察新主进程和 CDP；暂不改变界面。                                     | 只有一个主实例，仍使用同一日常 profile，用户确认同一账号和同一聊天可用；匹配的主界面只读探针成功。 |
| 3. 重复与互斥 | 工作实例存在时再次点击专用入口，核对只复用、不另启；随后正常退出，再用专用入口冷启动一次。 | 没有第二个主实例；退出后旧连接与端口消失；第二次冷启动无需手动补参或重新登录。                     |
| 4. 撤销对照   | 停用辅助程序，正常退出测试实例，再点原入口冷启动。                                         | 原入口、包与日常账号/聊天仍可用；无本方案启动的 CDP 监听、辅助进程或适配痕迹。                     |

若要求登录或出现新的数据路径，不在实验窗口重新登录；停止验证，回到原入口确认状态。日志只保留路径是否一致、包版本、进程/监听归属、目标 URL 和检查结果，不记录凭据或聊天内容。

## 停用和进入 P1

- **即时停用适配**：P1 提供独立停用开关，立即清除自己插入的样式与节点，停止接入。CDP 若由启动参数开启，控制器断开不等于端口关闭；已启动的 Codex 不因切换开关而重启。
- **彻底撤销**：用户正常退出带调试参数的实例，用原入口启动，确认端口关闭。卸载仅移除新增的专用快捷方式、启动器和它自己的配置；不移除原包、不清理日常 profile。
- **专用入口 P0b 通过后**：P1 仅在匹配版本的真实主界面加入单一静态渐变和即时停用。经专用入口做三次冷启动，确认自动加载、只加载一次、停用当场恢复且重开保持停用；原入口作为普通启动和撤销对照。面板、播放器、素材库与长期验收留在后续阶段。
