# Codex P0b：原入口、日常 profile 与可撤销 CDP 验证

日期：2026-11-10（Asia/Shanghai）。范围：接入研究与有界诊断。未安装自动接入器，未注入脚本/样式/壁纸，未进入 P1 或完整实现。

## 当前结论

**P0b 整体门槛尚未通过。** 当前工作中的日常实例没有 CDP 监听端口；通过原注册 AUMID 热激活并追加调试启动参数，没有给它补开端口。当前约束下，没有验证出一种能为这个已运行实例无重启启用 CDP 的方式。

**辅助程序先启动、普通入口再复用**的先后顺序，在专用测试 profile 内得到正向证据：同一官方 EXE、同一测试 profile，先带 CDP 启动，后续无 CDP 参数启动会转交给已有实例；有界连接探针自动发现主界面并成功执行只读请求，关闭 WebSocket 后也可以重连。

这不是“原 AUMID + 已登录日常 profile 的冷启动自动接入”通过证据。测试 profile 没有日常账户和聊天；测试中的普通入口是带相同测试 profile 参数的原 EXE，不能改称 Windows 原注册入口。保留原图标、所有启动来源均自动生效、冷启动竞争和账户兼容性仍未通过。

**当前工作实例没有关闭或重启。** 最终主 PID `23900` 的创建时间仍为 `1794183743.8887403`，调试参数未变；所有实验进程和端口已退出，EXE、ASAR、清单、Owl 配置及盘点到的快捷方式散列保持一致。

## 登录窗口干扰与处理

用户在本轮现场报告“为什么一直在打开 Codex 的登录界面”。这些实验使用独立空白 profile 和独立 CODEX_HOME，没有借用日常登录凭据，因此出现登录页符合测试环境状态；不能据此判定日常账号掉线。

探针设置了 Windows `SW_HIDE`、`CREATE_NO_WINDOW` 和子进程 `CODEX_ELECTRON_START_IN_BACKGROUND=1`，但这些参数没有阻止用户看到实验登录窗口。**本轮不能记为“隐藏运行通过”**；没有录制窗口画面，实际显示问题以用户现场反馈为证据。两轮实验共发起 9 次原 EXE 启动请求，其中 4 次是同 profile 单实例转交，5 次是持续到对应测试结束的实验主实例；另有 1 次原 AUMID 热激活。

收到反馈后立即停止新实例实验，只继续进程核对、缓存归档和证据整理。随后核对只有原工作主实例，所有实验进程均不存在、5 个实验端口均无监听。没有要求用户登录测试窗口，也没有终止日常实例。[中断后的状态核对](../../.scratch/codex-cdp-p0b/user-interruption-health.json)

后续本机验证不得继续把隐藏启动参数当作无窗口保证。需要冷启动或新 GUI 实例的验证另行明确实验窗口影响和时机，本轮不继续启动。

## 可撤销性与恢复结果

本轮区分三种恢复：

1. **控制器断开**：只读 WebSocket 均关闭；实验实测 CDP listener 继续存在。不能把关闭辅助程序说成端口也关闭。
2. **移除调试启动参数后的恢复**：第二轮只退出该轮实验进程，再以同一个测试 profile、不带 CDP 参数启动。`11:37:32` PID `31304` 保持运行，测试 sentinel 未变，旧 CDP 端口和该轮所有应用 listener 均无监听。只验证了测试 profile 的启动恢复，没有退出日常 Codex。
3. **最终实验清理**：所有本轮 owned PID 复核创建时间后已退出，5 个端口 `60562`、`52839`、`62179`、`49668`、`57344` 均无监听。当前日常主实例仍在，安装文件与入口文件散列核对未变。

因本轮没有安装持久配置，没有要卸载的服务、任务或注册表项；不将此表述为产品级一键卸载已验收。

四个测试数据目录经绝对路径边界核对，已保留并移到 `C:\Users\614\AppData\Local\Temp\codex-wallpaper-p0b-20261110-1140`；没有删除缓存，也没有将其纳入仓库。[归档结果](../../.scratch/codex-cdp-p0b/archive-result.json)、[最终日常实例状态](../../.scratch/codex-cdp-p0b/run-20261110-1134/final-health.json)、[进程/端口/入口文件完整性复核](../../.scratch/codex-cdp-p0b/verification.json)

首次实验还保留其执行时的 [probe-used.py](../../.scratch/codex-cdp-p0b/run-20261110-1134/probe-used.py) 与散列；后来为第二轮补充了不带 CDP 的重新启动恢复检查。[当前诊断脚本](../../.scratch/codex-cdp-p0b/probe.py) 和 [AUMID 激活脚本](../../.scratch/codex-cdp-p0b/activate-entry.ps1) 会启动进程或激活应用，不是无副作用的只读分析命令；本轮结束后不再自动重跑。

## 入口盘点中的额外发现

桌面、用户/公共开始菜单与用户任务栏快捷方式目录的有界盘点发现：

- 已注册的原包 AUMID 仍存在，激活成功。
- 用户开始菜单的 `Programs\ChatGPT.lnk` 指向旧第三方 `DragonCodexBoot.exe`，目标文件目前不存在；它与包注册入口不是同一个东西。
- 另外存在 Dream Skin 和日志入口，不能把它们自动视为本项目已确认的原入口。只读取快捷方式元数据与散列，未运行其脚本或修改链接。
- 当前原主进程父进程为 `explorer.exe`；不能根据旧链接推断当前工作实例由该第三方启动器启动。

这要求未来冷启动验收记录**实际点击/激活了哪个入口**，不能仅记录“点击 ChatGPT”。本轮不顺带修复或替换其他项目留下的链接。
