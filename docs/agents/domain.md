# Domain Docs

本项目采用 single-context。
工程技能在探索项目及提出修改方案时，遵循以下领域文档规则。

## 阅读入口

- 探索前阅读根目录的 `GLOSSARY.md`。
- 开展某个领域的工作前，阅读 `docs/adr/` 中与该领域相关的 ADR。
- 如果上述文件或目录不存在，直接继续；
  不必报告缺失，也不要预先创建占位内容。
- 术语或架构决定在讨论中明确后，
  由 `domain-modeling` 工作流按需补充相应文档。

## 文档布局

- 术语表：根目录 `GLOSSARY.md`。
- 架构决定：`docs/adr/NNNN-<slug>.md`。
- 不创建 `GLOSSARY-MAP.md` 或按子目录拆分的领域文档。

现有需求基线和验收资料位于 `docs/planning/`。
涉及产品范围、已确认需求或验收标准时，查阅相关规划文档；
这些资料不替代术语表或 ADR。

## 使用术语表中的词汇

在任务标题、方案、假设、代码和测试中命名领域概念时，
使用 `GLOSSARY.md` 中定义的术语，
避免使用术语表明确要求避免的同义词。

需要的概念尚未收录时，先判断是否已有对应术语；
确有缺口时，交由 `domain-modeling` 工作流明确后补充，
不要自行把未确认的概念写成既定定义。

## 显式指出 ADR 冲突

如果方案与已有 ADR 冲突，明确指出相关 ADR 和重新讨论的理由，
不要静默覆盖已经记录的架构决定。
