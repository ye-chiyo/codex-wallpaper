# Codex Wallpaper：Windows 版 Codex のローカル壁紙と UI 適応

[简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md)

> **プロジェクト状態：暫定リリース候補。** このスナップショットには実行可能な候補実装と一部のオフライン検証が含まれていますが、実際の Codex エンドツーエンド確認、ログイン／再起動、リソース予算、長期的な安定性は未確認です。この README は候補の提供範囲を説明するもので、受け入れ合格を意味しません。
>
> **非公式ツール：** OpenAI の公式機能ではなく、OpenAI による互換性や安全性の承認を示すものでもありません。専用ランチャーがローカルの Codex を確認したうえで、メイン画面にローカル壁紙と UI 適応を追加します。

## 概要

Codex Wallpaper は Windows 版 Codex デスクトップアプリ向けのツールです。ローカル画像、動画、ローカルに導入済みの Wallpaper Engine コンテンツ、静的な Web 背景を Codex のメイン画面の背後に表示し、チャット、ツールカード、サイドバー、設定、入力欄の可読性と視覚的な階層を調整します。

Codex のパッケージを書き換えたり、アカウントやチャットデータを置き換えたりはしません。基本の入口は `launcher/Codex-Wallpaper.cmd` です。テスターは [launcher/README.md](launcher/README.md) の任意手順に従って C# デスクトップ起動層を個別にビルドできます。元の Codex エントリは、現時点では壁紙レイヤーを自動的に接続できません。本プロジェクトは既存の Codex、デスクトップ、タスクバーのショートカットを置換または変更しません。候補は Codex パッケージの正確なバージョン、アプリ登録、元の実行ファイルのハッシュを確認し、一致しない場合は元の UI をそのまま維持します。

## 機能と状態

状態の定義：

- **実装済み候補**：公開ソースに対応する処理経路はありますが、実際のホストでの受け入れ完了を意味しません。
- **直接再生／ネイティブ描画**：静止サムネイルではなく、ブラウザのメディア要素または WebWallGL が直接表示します。
- **プレビューへのフォールバック**：直接再生できない場合、Wallpaper Engine の作者プレビューを表示します。
- **非対応**：現在の候補には実装がありません。
- **未検証**：関連するコードはあっても、動作を保証できるだけの実機検証がありません。

## クイックスタート

以下のコマンドはリポジトリのルートで実行します。個人の絶対パスを使わず、相対パスまたは一般的なパスで示しています。

1. リポジトリを取得し、依存関係をインストールします。候補テスターは複製後にリリース確認ブランチを追跡できます。

```powershell
git clone https://github.com/ye-chiyo/codex-wallpaper.git
Set-Location .\codex-wallpaper
# 候補テスター向けの任意コマンド: git switch --track origin/codex/release-review
pnpm install --frozen-lockfile
```

2. インストール済み Codex パッケージのバージョンを確認します。

```powershell
Get-AppxPackage -Name OpenAI.Codex | Select-Object PackageFullName, Version
```

ランチャーが受け入れるのは確認済みの `26.1111.2228.0` と `26.1117.3838.0` です。Codex 更新後はまず元のエントリを使用してください。パッケージ、アプリ登録、実行ファイルのハッシュが一致しない場合、専用ランチャーは接続前に停止し、元の UI を維持します。

3. **Codex を完全に終了します。** ウィンドウを閉じるだけ、または最小化するだけでは終了になりません。Codex のメインプロセスが残っていないことを確認してから、専用エントリを実行します。

```powershell
.\launcher\Codex-Wallpaper.cmd
```

`Codex-Wallpaper.cmd` が基本の起動経路です。任意の C# デスクトップ起動層は起動画面と非表示コンソールだけを提供し、製品版、パッケージ、既存ショートカットを変更しません。ビルドと使用方法は [launcher/README.md](launcher/README.md) に記載します。

4. 初回の成功時は通常、次のように表示されます。

```text
Outcome: wallpaper-ready
Wallpaper: enabled
```

ページ内で以前に壁紙を無効化していた場合、`Wallpaper` は `disabled` になることがあります。`Outcome: wallpaper-ready` は、コード上の起動とメイン画面の確認を経て宿主準備完了のハンドシェイクに到達したことを示します。アカウント、チャット、UI、メディア、再起動、長期安定性の実機受け入れを代替しません。

5. 元のアカウントと既存チャットが利用できること、チャット、ツールカード、コード／差分、入力欄、左右のサイドバーが読みやすく操作できることを確認します。ログイン画面が出た場合は、この検証用インスタンスではログインせず、終了して元のエントリで状態を確認してください。

6. 起動、接続、注入を行わずに現在のインスタンス状態だけを確認するには、次を実行します。

```powershell
powershell.exe -NoProfile -STA -File .\launcher\Start-CodexWallpaper.ps1
```

元のエントリから起動した通常のインスタンスでは、`DebugFlag: false` と `ListeningPorts: []` が期待されます。このコマンドは実行中のインスタンスを変更しません。

開発時には `pnpm test` で Node テストを実行できます。自動テストや headless fixture は、実際の Codex での受け入れ確認の代わりにはなりません。

## 日常的な使い方

壁紙の実行中に `Alt+Shift+S` を押すと設定パネルが開閉します。現在の UI 文言は簡体字中国語のみです。この文書では実際の中国語ラベルをそのまま残し、翻訳を併記します。

| ----------------------- | ------------------------------------- | -------------------------------------------- |
| `壁纸设置`              | Wallpaper settings                    | 壁紙設定                                     |
| `壁纸库`                | Wallpaper library                     | 壁紙ライブラリ                               |
| `播放与性能`            | Playback and performance              | 再生とパフォーマンス                         |
| `外观与预设`            | Appearance and presets                | 外観とプリセット                             |
| `导入素材`              | Import assets                         | 素材をインポート                             |
| `使用`                  | Use                                   | 使用                                         |
| `收藏`                  | Favorite                              | お気に入り                                   |
| `加入轮播` / `移除轮播` | Add to / remove from rotation         | ローテーションに追加 / から削除              |
| `保存当前设置`          | Save current settings                 | 現在の設定を保存                             |
| `导出设置` / `导入设置` | Export / import settings              | 設定をエクスポート / インポート              |
| `移除全部导入素材`      | Remove all imported assets            | インポート素材をすべて削除                   |
| `停用并清除本项目数据`  | Disable and clear this project’s data | 壁紙を無効化して本プロジェクトのデータを消去 |
| `再次点击确认清除`      | Click again to confirm deletion       | もう一度クリックして消去を確定               |

基本的な流れ：

1. `Alt+Shift+S` を押して `壁纸设置` を開き、`壁纸库` から内蔵背景、インポート素材、ローカルの Wallpaper Engine プロジェクトを選びます。
2. `使用` を押して壁紙を切り替えます。素材がない、または読み込めない場合、ページはその項目をスキップするか現在の表示を維持します。
3. 星印ボタンでお気に入りを管理し、`加入轮播`／`移除轮播` でローテーションのプレイリストを編集します。ローテーションには 2 項目以上が必要で、0 分では無効です。
4. `播放与性能` で性能プロファイル、Scene 上限、ミュート、音量、ローテーションを調整します。`外观与预设` で壁紙表示、UI の可読面、セクション別上書き、プリセット、設定の入出力を調整できます。設定は同一オリジンのウィンドウ間で同期されます。
5. `Alt+Shift+W` で背景と設定パネルを消し、もう一度押すと最後に有効だった壁紙と設定を復元します。

外観設定：

| 設定           | 範囲と既定値              | 説明                                                 |
| -------------- | ------------------------- | ---------------------------------------------------- |
| 暗化           | 0〜70%、既定 18%          | 背景を暗くして文字の可読性を上げる                   |
| ぼかし         | 0〜24 px、既定 0          | メディアレイヤーをぼかす                             |
| 不透明度       | 20〜100%、既定 100%       | メディアレイヤーの透明度を調整する                   |
| フレームレート | 15 または 30 FPS、既定 30 | Scene と互換描画の上限フレームレート                 |
| 音量           | 0〜100%、既定 0           | 0 はミュート。音声付き動画と素材音声は実機確認が必要 |
| ローテーション | 0〜120 分、既定 0         | 2 項目以上かつ 0 より大きい場合だけ有効              |
| 画面の可読面   | 20〜100%、既定 72%        | Codex UI の可読レイヤー濃度を調整                    |
| UI ぼかし      | 0〜24 px、既定 0          | UI の可読レイヤーをぼかす                            |

既定では、ページが非表示を報告すると動画と Scene を一時停止し、再表示時に再開します。可視性はウィンドウごとに判断されますが、同一オリジンの設定は共有されます。

## Windows ログイン時の起動（任意、受け入れ未完了）

この公開スナップショットには任意のログイン起動用コマンドが実装されています。操作対象は現在のユーザーの Startup フォルダーにある `Codex Wallpaper.lnk` のみです。Windows サービス、スケジュールタスク、システム全体のスタートアップ項目は登録せず、ショートカットは非表示ウィンドウで専用ランチャーを起動します。既存の Codex、デスクトップ、タスクバーのショートカットは変更しません。

> **受け入れ状態：** リリース記録では、実際のログイン、サインアウト、再起動、重複起動の受け入れが完了していません。長期的に安定しているとは表現できません。

```powershell
# 現在のユーザーのログインエントリを有効化、または冪等に更新
powershell.exe -NoProfile -STA -File .\launcher\Start-CodexWallpaper.ps1 -EnableStartup

# 状態を確認。JSON の Status は enabled、stale、disabled のいずれか
powershell.exe -NoProfile -STA -File .\launcher\Start-CodexWallpaper.ps1 -StartupStatus

# ログイン時の起動を削除
powershell.exe -NoProfile -STA -File .\launcher\Start-CodexWallpaper.ps1 -DisableStartup
```

ログインエントリは既存の専用ランチャーを `-Launch -Unattended` で呼び出します。検証可能な専用インスタンスが既に動作している場合は、そのインスタンスを再利用します。通常の Codex インスタンス、複数のメインプロセス、一致するレシートがない場合は、再利用可能な専用インスタンスとは扱いません。無人起動のレシートは `%LOCALAPPDATA%\CodexWallpaper\P0b` に保存されます。

## 無効化とアンインストール

必要な段階だけを実行してください。壁紙ツールを削除するために、Codex の通常使用プロファイル、ログインデータ、チャットを削除しないでください。

1. **一時的に壁紙を無効化：** 専用 Codex ページにキーボードフォーカスがある状態で `Alt+Shift+W` を押します。もう一度押すと復元されます。ページ内で無効化しても、専用ランチャーが作成したデバッグリスナーは閉じません。リスナーは Codex インスタンスを正常終了した時に終了します。
2. **ログイン時の起動を停止：** `-DisableStartup` を実行し、状態が `disabled` であることを確認します。
3. **このプロジェクトのページデータを消去：** `Alt+Shift+S` で設定を開き、`外观与预设`（外観とプリセット）を選びます。 `停用并清除本项目数据` を押し、続いて `再次点击确认清除` を押します。ページのグローバル設定と IndexedDB 内のインポート素材が削除され、内蔵グラデーションに戻ります。Codex の通常プロファイル、アカウント、チャットは削除しません。
4. **レシートと自前のローカルファイルを削除：** `launcher\Reset-CodexWallpaper.cmd` をダブルクリックします。このスクリプトは `%LOCALAPPDATA%\CodexWallpaper` のみを処理し、ページの IndexedDB 内のインポート素材は消去しないため、先に手順 3 を完了してください。
5. **元のエントリに戻す：** 専用 Codex インスタンスを完全に終了し、元の Codex エントリから起動します。元のエントリはインストーラーや本プロジェクトによって置き換えられていません。
6. **ツール自体を削除：** 上記の手順を終えた後、このリポジトリのローカルチェックアウトを削除できます。システムレベルのインストーラーや別の自動アンインストーラーはありません。

壁紙を「アンインストール」するために `%APPDATA%\Codex\web\Codex`、`%LOCALAPPDATA%\Packages\OpenAI.Codex_2p2nqsd0c76g0`、その他の Codex データディレクトリを削除しないでください。これらは本プロジェクトのものではありません。

## よくある問題

### 起動しても壁紙が表示されない

Codex を完全に終了したことを確認し、`launcher\Codex-Wallpaper.cmd` をもう一度実行してください。検証済みの専用インスタンスは再利用できます。通常のインスタンスは元の画面のまま動作します。パッケージが対応版 `26.1111.2228.0` または `26.1117.3838.0` か確認し、コンソールの `Outcome` を確認してください。状態確認コマンドは読み取り専用で、注入は行いません。

### `Alt+Shift+S` または `Alt+Shift+W` に反応しない

ショートカットは壁紙が動作するページ内に登録されるもので、システム全体のグローバルホットキーではありません。専用 Codex ウィンドウをクリックしてページにキーボードフォーカスを与えてから再試行してください。ページが無効なときは設定パネルがないため、先に `Alt+Shift+W` で復元します。それでも動かない場合はランチャーの `Outcome` と `Wallpaper.state` を確認します。

### バージョンまたは実行ファイルの不一致が表示される

ランチャーはパッケージ、AppID、インストールパス、実行ファイルの SHA-256、通常プロファイルを正確に確認します。Codex 更新後に `Unsupported or ambiguous Codex package`、`Original executable or app registration did not match`、`daily-profile-missing` が出た場合は、確認を回避しないでください。元のエントリを使用し、新しいバージョンに対応したリリースを待ちます。

### Wallpaper Engine の素材が再生されない

候補が扱うのはローカルにダウンロード済みのプロジェクトであり、Wallpaper Engine Workshop 全体の互換性を保証するものではありません。動画のメイン素材はローカル File 経路で 1 GiB まで、その他の素材と互換フォールバックは 512 MiB までです。上限超過、読み込み失敗、レンダラー利用不可の場合は作者プレビューになることがあります。オフライン Web がスクリプトを含む、HTML が 512 KiB を超える、外部リソースに依存する場合も降格します。オンライン Web は非対応です。

### 切り替え時に黒画面、停止、古い画像が残る

大きな Scene や動画はオンデマンドで読み込まれます。現在の切り替えが終わるのを待ってから別の項目を選び、必要なら `Alt+Shift+W` を 1 回押して無効化・復元してください。再現する場合は、発生時刻、素材の種類、レシートの `Outcome` を残してください。チャット本文、アカウント情報、未確認の完全なレシートを添付しないでください。

### ログイン画面が出る、またはアカウント状態がおかしい

検証用インスタンス内でログインしないでください。完全に終了し、元の Codex エントリで元のアカウントと既存チャットを確認します。元のエントリが正常なら、レシートの `Outcome` と `NativeProfile` を診断情報として使います。プロファイルをコピーしたりアップロードしたりしないでください。

### ログイン時の起動が動作しない

`-StartupStatus` を実行します。`stale` は同名ショートカットが古いパスまたは引数を指している状態です。`-DisableStartup` を実行してから `-EnableStartup` を実行してください。実際のサインアウト／再起動の受け入れは未完了なので、この機能から Codex のログイン状態や素材分離が検証済みだと判断しないでください。

### 必要な診断情報

```powershell
powershell.exe -NoProfile -STA -File .\launcher\Start-CodexWallpaper.ps1
Get-ChildItem "$env:LOCALAPPDATA\CodexWallpaper\P0b" -Filter *.json |
  Select-Object Name, LastWriteTime
```

レシートには PID、ローカルパス、プロセス時刻などのメタデータが含まれることがあります。共有前に確認して秘匿情報を除去してください。Codex プロファイル、認証情報、チャット内容をアップロードしないでください。

## 既知の制限

- 開発候補であり、すべての受け入れ項目を完了した安定版ではありません。
- Windows のみ対応しています。macOS、Linux、モバイル向けの実装はありません。
- Codex `26.1111.2228.0` と `26.1117.3838.0` の記録済み識別情報のみに対応します。Codex 更新時には互換アップデートが必要で、パッケージ、登録、ハッシュ、メイン画面の確認を回避してはいけません。
- 元の Codex エントリは壁紙を自動接続できません。必ず専用ランチャーから起動します。
- UI 文言は簡体字中国語のみです。README の翻訳は多言語 UI を意味しません。
- オンライン Web 壁紙は非対応です。オフライン Web はスクリプトを実行できず、外部リソースも読み込めません。
- すべての Wallpaper Engine 素材の再生は保証できません。動画は 1 GiB、その他の素材と互換フォールバックは 512 MiB までです。Scene の網羅率、DPI 間の挙動、テーマの組み合わせ、複数ウィンドウのリソースコスト、障害復旧は個別に検証が必要です。
- 実際のログイン／再起動を含む Startup の受け入れ、完全な実機ホスト操作マトリクス、30〜60 分のリソース比較、8 時間の基礎確認、7 日間の観察は未完了です。
- 自動テストと headless fixture は、対象にしたルールだけを証明し、実際の Codex の全ウィンドウ、パネル、境界ケースを証明しません。
