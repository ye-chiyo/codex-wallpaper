[简体中文](README.md) | [English](README.en.md) | [日本語](README.ja.md)

## 概要

Codex Wallpaper は Windows 版 Codex デスクトップアプリ向けのツールです。ローカル画像、動画、ローカルに導入済みの Wallpaper Engine コンテンツ、静的な Web 背景を Codex のメイン画面の背後に表示し、チャット、ツールカード、サイドバー、設定、入力欄の可読性と視覚的な階層を調整します。

Codex のパッケージを書き換えたり、アカウントやチャットデータを置き換えたりはしません。基本の入口は `launcher/Codex-Wallpaper.cmd` です。テスターは [launcher/README.md](launcher/README.md) の任意手順に従って C# デスクトップ起動層を個別にビルドできます。元の Codex エントリは、現時点では壁紙レイヤーを自動的に接続できません。本プロジェクトは既存の Codex、デスクトップ、タスクバーのショートカットを置換または変更しません。候補は Codex パッケージの正確なバージョン、アプリ登録、元の実行ファイルのハッシュを確認し、一致しない場合は元の UI をそのまま維持します。

自作部分のソースは閲覧用に公開しています。利用範囲は[上流ソースとライセンス](#上流ソースとライセンス)を参照してください。

## クイックスタート

PowerShell で次の手順を順に実行します。

1. **ソースを取得します。** GitHub の既定ブランチを取得し、リポジトリのルートに移動します。

   ```powershell
   git clone https://github.com/ye-chiyo/codex-wallpaper.git
   Set-Location .\codex-wallpaper
   ```

2. **インストール済みの Codex パッケージを確認します。** 結果が 1 件で、`PackageFullName` が互換性表のいずれかと完全に一致する場合に、依存関係のインストールに進みます。結果が 0 件または複数件の場合やパッケージ名が異なる場合は、壁紙プロジェクトが対応するまで、Windows のスタートメニューから公式の Codex を起動してください。

   ```powershell
   Get-AppxPackage -Name OpenAI.Codex | Select-Object PackageFullName, Version
   ```

3. **ツールとロック済みの依存関係をインストールします。** [Node.js 公式アーカイブ](https://nodejs.org/en/download/archive/v24.16.0)の Windows x64 MSI をインストールし、新しい PowerShell を開いてリポジトリのルートに戻ります。Node.js に同梱される npm で指定バージョンの [pnpm](https://pnpm.io/installation#using-npm) をインストールします。pnpm `11.25.0` を導入済みならグローバルインストールは省略できます。`node --version` が `v24.16.0`、`pnpm.cmd --version` が `11.25.0` であることを確認してください。

   ```powershell
   node --version
   npm.cmd install --global pnpm@11.25.0
   pnpm.cmd --version
   ```

   バージョンが一致したら、リポジトリのルートでロック済みの依存関係をインストールします。

   ```powershell
   pnpm.cmd install --frozen-lockfile
   ```

4. **まず公式の Codex を起動して初期設定を済ませます。** Windows のスタートメニューから Codex を開き、必要ならログインします。メイン画面が表示されたら、アカウントと既存のチャットにアクセスできることを確認します。新規アカウントでは、新しいチャットを開けることを確認してください。その後 Codex を通常の手順で完全に終了し、メインプロセスが終了するまで待ちます。ウィンドウを閉じたり最小化したりしても、バックグラウンドで動作し続けることがあります。

5. **メイン画面の壁紙を起動します。** リポジトリのルートで専用の CMD を実行します。

   ```powershell
   .\launcher\Codex-Wallpaper.cmd
   ```

   ```text
   Outcome: wallpaper-ready
   Wallpaper: enabled
   ```

   `Outcome: wallpaper-ready` は、メイン画面の確認が済み、壁紙ホストの準備が完了したことを示します。`Wallpaper: enabled` のときはメイン画面に壁紙が表示されます。以前に無効化した状態が保存されていた場合は `Wallpaper: disabled` になり、通常の画面が表示されます。Codex のウィンドウで `Alt+Shift+W` を押すと壁紙を再度有効にできます。チャットを開いて入力欄が使えることも確認してください。専用セッションでログイン画面が出たら、終了して公式の Codex で初期設定を済ませてください。途中で停止した場合は、コンソールのメッセージを確認し、[よくある問題](#よくある問題)の該当項目を参照してください。

Codex が完全に終了したか確認するには、リポジトリのルートで次の読み取り専用コマンドを実行します。

```powershell
powershell.exe -NoProfile -STA -File .\launcher\Start-CodexWallpaper.ps1
```

対応パッケージで `"Running": []` が表示されれば、Codex のメインプロセスは検出されていません。公式の入口から起動した通常のインスタンスでは `DebugFlag: false` と `ListeningPorts: []` が表示されます。

リリースチェックでは `pnpm.cmd test:full` を実行します。Node.js テストと 4 つの Windows PowerShell フィクスチャを順番に実行し、各スイートの所要時間と終了コードを表示します。Edge、ffmpeg、PowerShell COM がない場合は `BLOCKED` と記録します。Node.js テストだけを試す場合は `pnpm.cmd test` を使用できます。フィクスチャと実機での結果は[候補の検証記録](docs/planning/codex-wallpaper-candidate.md)に記載しています。

## 日常的な使い方

壁紙の実行中に `Alt+Shift+S` を押すと設定パネルが開閉します。現在の UI 文言は簡体字中国語のみです。この文書では実際の中国語ラベルをそのまま残し、翻訳を併記します。

| 中国語 UI 表記          | English                               | 日本語                                       |
| ----------------------- | ------------------------------------- | -------------------------------------------- |
| `壁纸设置`              | Wallpaper settings                    | 壁紙設定                                     |
| `壁纸库`                | Wallpaper library                     | 壁紙ライブラリ                               |
| `播放与性能`            | Playback and performance              | 再生とパフォーマンス                         |
| `外观与预设`            | Appearance and presets                | 外観とプリセット                             |
| `导入素材`              | Import assets                         | 素材をインポート                             |
| `使用`                  | Use                                   | 使用                                         |
| `收藏`                  | Favorite                              | お気に入り                                   |
| `加入轮播` / `移除轮播` | Add to / remove from rotation         | ローテーションに追加 / から削除              |
| `保存当前设置`          | Save current settings                 | 現在の設定を保存                             |
| `导出设置` / `导入设置` | Export / import settings              | 設定をエクスポート / インポート              |
| `移除全部导入素材`      | Remove all imported assets            | インポート素材をすべて削除                   |
| `停用并清除本项目数据`  | Disable and clear this project’s data | 壁紙を無効化して本プロジェクトのデータを消去 |
| `再次点击确认清除`      | Click again to confirm deletion       | もう一度クリックして消去を確定               |

基本的な流れ：

1. `Alt+Shift+S` を押して `壁纸设置` を開き、`壁纸库` から内蔵背景、インポート素材、ローカルの Wallpaper Engine プロジェクトを選びます。
2. `使用` を押して壁紙を切り替えます。素材がない、または読み込めない場合、ページはその項目をスキップするか現在の表示を維持します。
3. 星印ボタンでお気に入りを管理し、`加入轮播`／`移除轮播` でローテーションのプレイリストを編集します。ローテーションには 2 項目以上が必要で、0 分では無効です。
4. `播放与性能` で性能プロファイル、Scene 上限、ミュート、音量、ローテーションを調整します。`外观与预设` で壁紙表示、UI の可読面、セクション別上書き、プリセット、設定の入出力を調整できます。同一オリジンのページ間で設定を同期します。実機の複数の Codex メインウィンドウでの壁紙表示は未確認です。
5. `Alt+Shift+W` で背景と設定パネルを消し、もう一度押すと最後に有効だった壁紙と設定を復元します。

外観設定：

| 設定           | 範囲と既定値                                                          | 説明                                                     |
| -------------- | --------------------------------------------------------------------- | -------------------------------------------------------- |
| 暗化           | 0〜70%、既定 18%                                                      | 背景を暗くして文字の可読性を上げる                       |
| ぼかし         | 0〜24 px、既定 0                                                      | メディアレイヤーをぼかす                                 |
| 不透明度       | 20〜100%、既定 100%                                                   | メディアレイヤーの透明度を調整する                       |
| フレームレート | パフォーマンス優先 15 FPS、バランス 30 FPS（既定）、カスタム 1–30 FPS | Scene の描画上限。動画は元ファイルのフレームレートで再生 |
| 音量           | 0〜100%、既定 0                                                       | 0 はミュート。音声付き動画と素材音声は実機確認が必要     |
| ローテーション | 0〜120 分、既定 0                                                     | 2 項目以上かつ 0 より大きい場合だけ有効                  |
| 画面の可読面   | 20〜100%、既定 72%                                                    | Codex UI の可読レイヤー濃度を調整                        |
| UI ぼかし      | 0〜24 px、既定 0                                                      | UI の可読レイヤーをぼかす                                |

動画と Scene は既定で、そのページが非表示のときに一時停止し、再表示時に再開します。オフライン Web のフレームレートと一時停止はサンドボックス内のコンテンツに依存します。

## 無効化とアンインストール

### 壁紙ツールを更新する

古い専用 Codex インスタンスを通常の手順で完全に終了してから、ソースを更新します。Codex のパッケージを再確認し、ロック済みの依存関係をインストールしてから、[クイックスタート](#クイックスタート)に従って新しい専用 CMD を実行します。専用インスタンスが検証済みであれば、再実行時にそのインスタンスを再利用します。通常の Codex が動作中なら接続を中止します。`Outcome: runtime-version-mismatch` が出たら、Codex を完全に終了し、更新後の専用 CMD で開き直してください。既に読み込まれている壁紙ランタイムはそのまま維持されます。

### 一時的に無効化する

フォーカスのある Codex ウィンドウで `Alt+Shift+W` を押します。もう一度押すと前の壁紙と設定に戻ります。無効化すると壁紙レイヤーとプレーヤーが取り外されます。専用のデバッグ用リスナーは Codex が完全に終了した時点で閉じます。

### データを消去して公式の入口に戻る

1. **先にページ内データを消去します。** 専用インスタンスで `Alt+Shift+S` を押し、`外观与预设`（外観とプリセット）を開きます。`停用并清除本项目数据`、`再次点击确认清除` の順にクリックします。壁紙を無効化し、プロジェクトのページ設定と IndexedDB のインポート素材を消去します。一時的に無効化している場合は、壁紙を有効に戻して設定を開いてください。
2. **設定していた場合はログイン時の起動を解除します。** `-DisableStartup` を実行し、`-StartupStatus` の `Status` が `disabled` であることを確認します。[ログイン時の起動コマンド](launcher/README.md#windows-登录启动)
3. **専用 Codex を完全に終了します。** 必要ならクイックスタートの読み取り専用コマンドを実行し、`"Running": []` を確認します。
4. **ローカルの起動記録とキャッシュを消去します。** 終了後に `launcher\Reset-CodexWallpaper.cmd` を実行して `%LOCALAPPDATA%\CodexWallpaper` を消去します。
5. **公式の入口から Codex を開きます。** スタートメニューから起動し、アカウントと既存チャットが使えることを確認します。ツールを完全に削除する場合は、ローカルの作業コピーと自分で作成した壁紙用のショートカットを削除できます。

Codex の通常プロファイル、アカウントデータ、チャットは保持してください。ページ内の消去とローカルのリセットは壁紙プロジェクトのデータだけを対象にします。

## よくある問題

### 起動しても壁紙が表示されない

Codex を完全に終了したことを確認し、`launcher\Codex-Wallpaper.cmd` をもう一度実行してください。検証済みの専用インスタンスは再利用できます。通常のインスタンスは元の画面のまま動作します。パッケージが対応版 `26.1111.2228.0` または `26.1117.3838.0` か確認し、コンソールの `Outcome` を確認してください。状態確認コマンドは読み取り専用で、注入は行いません。

### `Alt+Shift+S` または `Alt+Shift+W` に反応しない

ショートカットは壁紙が動作するページ内に登録されるもので、システム全体のグローバルホットキーではありません。専用 Codex ウィンドウをクリックしてページにキーボードフォーカスを与えてから再試行してください。ページが無効なときは設定パネルがないため、先に `Alt+Shift+W` で復元します。それでも動かない場合はランチャーの `Outcome` と `Wallpaper.state` を確認します。

### 初回起動時に通常プロファイルが見つからない

コンソールに `Expected daily profile directory is missing` と表示された場合は、Windows のスタートメニューから公式の Codex を開いて[クイックスタート](#クイックスタート)の手順 4 を済ませてから、専用の CMD を再試行してください。同じエラーが続く場合は公式の入口を使用してください。無人起動モードでは、このエラーは起動記録に `daily-profile-missing` として記録されます。

### バージョンまたは実行ファイルの不一致が表示される

- `Unsupported or ambiguous Codex package`（無人起動時の記録 `unsupported-package`）。[クイックスタート](#クイックスタート)の手順 2 を実行し、一致する x64 MSIX が 1 件だけであることを確認してください。表にないバージョンに更新された場合は、壁紙プロジェクトが対応するまで公式の入口を使用してください。
- `Original executable or app registration did not match`（無人起動時の記録 `executable-or-app-registration-mismatch`）。パッケージ名が一致しても、EXE の SHA-256 または Windows のアプリ登録が一致しないことがあります。公式の入口から Codex が起動することを確認してください。専用の入口だけで不一致が続く場合は、調査用にメッセージを控えてください。

どちらの場合も、壁紙を適用する前にランチャーが停止します。この段階では、専用の CMD がコンソールにメッセージを表示します。パッケージ、アプリ登録、ハッシュのチェックは有効にしたまま、公式の入口から通常の画面を開いてください。

### Wallpaper Engine の素材が再生されない

対象はローカルにダウンロード済みのプロジェクトです。動画本体はローカルの File 経路で 1 GiB まで、その他の素材と互換転送は 512 MiB までです。オフライン Web の HTML が読み取れない場合、512 KiB を超える場合、`<script>` を含む場合は作者のプレビューを試します。外部リソースは遮断されるため、ローカルの内容だけが表示される場合があります。

### 切り替え時に黒画面、停止、古い画像が残る

大きな Scene や動画はオンデマンドで読み込まれます。現在の切り替えが終わるのを待ってから別の項目を選び、必要なら `Alt+Shift+W` を 1 回押して無効化・復元してください。再現する場合は、発生時刻、素材の種類、レシートの `Outcome` を残してください。チャット本文、アカウント情報、未確認の完全なレシートを添付しないでください。

### ログイン画面が出る、またはアカウント状態がおかしい

検証用インスタンス内でログインしないでください。完全に終了し、元の Codex エントリで元のアカウントと既存チャットを確認します。元のエントリが正常なら、レシートの `Outcome` と `NativeProfile` を診断情報として使います。プロファイルをコピーしたりアップロードしたりしないでください。

## 既知の制限

- 開発候補であり、すべての受け入れ項目を完了した安定版ではありません。
- Windows のみ対応しています。macOS、Linux、モバイル向けの実装はありません。
- Codex `26.1111.2228.0` と `26.1117.3838.0` の記録済み識別情報のみに対応します。Codex 更新時には互換アップデートが必要で、パッケージ、登録、ハッシュ、メイン画面の確認を回避してはいけません。
- 元の Codex エントリは壁紙を自動接続できません。必ず専用ランチャーから起動します。
- UI 文言は簡体字中国語のみです。README の翻訳は多言語 UI を意味しません。
- オンライン Web 壁紙は非対応です。オフライン Web はスクリプトを実行できず、外部リソースも読み込めません。
- すべての Wallpaper Engine 素材の再生は保証できません。動画は 1 GiB、その他の素材と互換フォールバックは 512 MiB までです。Scene の網羅率、DPI 間の挙動、テーマの組み合わせ、複数ウィンドウのリソースコスト、障害復旧は個別に検証が必要です。
- 実際のログイン／再起動を含む Startup の受け入れ、完全な実機ホスト操作マトリクス、30〜60 分のリソース比較、8 時間の基礎確認、7 日間の観察は未完了です。
- 自動テストと headless fixture は、対象にしたルールだけを証明し、実際の Codex の全ウィンドウ、パネル、境界ケースを証明しません。
