# Codex 主界面壁纸：统一半透明表面与精细边界

**Status:** ready-for-human

## Problem Statement

用户希望在 Codex 日常工作时既能欣赏清晰、连贯的主界面壁纸，也能轻松阅读长聊天、工具状态、代码和差异。此前候选的菜单、侧栏、对话与右侧面板各用不同底色：有的区域露出亮条，有的接近不透明；卡片与壁纸控件又像各自叠上去，整体割裂。用户已选定新版预览：四周通透、整个原有对话区更深、复杂内容局部加底，不改变 Codex 布局。

视觉调整还可能重现已知问题：顶部控件点不到、标题栏定位被覆盖导致「变更」切换时闪动、输入框外侧露出黑色横带，以及停用后恢复时挂回旧样式。旧候选的部分修复有证据，但新版尚未实现、加载或验收，不能继承这些结论。

## Solution

让同一主界面壁纸贯穿整个受支持的 Codex 主窗口。顶部菜单与标题栏、左侧图标栏和项目栏、右侧文件与「变更」外壳使用协调的半透明材质，以细线区分相邻表面。原有主对话区铺满一层相对更深的半透明读底，不新增狭窄阅读面板。正文和普通状态共享该底色；可展开的工具执行行、代码和差异保留必要的局部读底。输入框、标签、菜单、弹窗和壁纸控件使用一致的边界与交互状态，同时跟随 Codex 明暗主题并保留原有位置和操作。

## User Stories

1. 作为 Codex 用户，我希望壁纸在整个主窗口中连续可见，以便欣赏完整画面。
2. 作为 Codex 用户，我希望顶部菜单与聊天标题栏没有露底亮条，以便顶部看起来连贯。
3. 作为 Codex 用户，我希望左侧图标栏与项目栏共享协调的半透明底色，以便识别分区时仍能看到壁纸。
4. 作为 Codex 用户，我希望右侧文件与「变更」面板打开后仍透出同一壁纸，以便操作区与聊天保持一致。
5. 作为 Codex 用户，我希望更深的半透明读底铺满原有聊天区，以便阅读长对话，同时保留原来的内容宽度和布局。
6. 作为 Codex 用户，我希望正文、普通执行状态和辅助信息共享聊天读底，以便阅读不被重复的卡片边界打断。
7. 作为 Codex 用户，我希望可展开的工具执行行有清楚的局部读底和可辨识的状态，以便找到并操作它们。
8. 作为 Codex 用户，我希望代码块与差异保留局部对比和增删标识，以便阅读细节。
9. 作为 Codex 用户，我希望输入框保持清晰而外侧不出现大片黑底，以便专注输入并保持底部画面连续。
10. 作为 Codex 用户，我希望输入框、标签、下拉菜单和壁纸控件拥有协调的细边框和圆角，以便界面看起来整洁。
11. 作为 Codex 用户，我希望悬停、焦点、选中和禁用状态易于区分，以便知道当前操作的目标。
12. 作为 Codex 用户，我希望菜单、面板和壁纸设置打开后仍清楚可读，以便快速完成操作。
13. 作为 Codex 用户，我希望视觉材质随 Codex 明暗主题变化，以便换主题时文字仍有对比，且不会被套上固定紫色。
14. 作为 Codex 用户，我希望明亮、深色和细节复杂的壁纸都兼顾文字易读与主体清晰，以便自由选择素材。
15. 作为 Codex 用户，我希望保留自己设置的壁纸模糊、暗化和透明度，以便维持偏好的清晰度和读底平衡。
16. 作为 Codex 用户，我希望顶部目录下拉、聊天标题、文件与「变更」标签以及安全可测按钮响应鼠标，以便继续使用原有操作。
17. 作为 Codex 用户，我希望在标题栏原生空白区域拖动窗口、使用窗口控制，以便壁纸不改变 Windows 操作习惯。
18. 作为 Codex 用户，我希望仍能输入、选取文字、滚动和展开工具行，以便壁纸装饰不影响工作。
19. 作为 Codex 用户，我希望侧栏与右侧面板开合、窗口缩放后没有裁切、遮挡或接缝，以便自在调整工作区。
20. 作为 Codex 用户，我希望反复进入「变更」再回到聊天时不闪黑、不跳回默认背景，以便自然切换。
21. 作为 Codex 用户，我希望从已有壁纸库选择和切换素材时仍保持界面可用，以便检查不同素材的效果。
22. 作为 Codex 用户，我希望停用壁纸后恢复原生外观，重新启用时恢复当前版本的视觉方案和已保存设置，以便启停不导致样式回退。
23. 作为 Codex 用户，我希望使用专用入口恢复上次壁纸时看到已验收版本的效果，以便确认持续运行不是一次性的临时预览。

## Implementation Decisions

- 在现有壁纸运行时内集中管理外围半透明表面、对话读底、局部读底、细边界、圆角及交互状态。复用 Codex 主题色和已有组件；在已验证的宿主结构上收敛相邻规则，避免持续追加互相覆盖的 CSS 补丁。预览中的紫色来自示例壁纸，不固化示例颜色、尺寸或透明度。
- 同一主界面壁纸为连续画面来源，外围表面可透出，聊天读底覆盖原有对话区，局部读底只服务工具、代码、差异、输入和菜单等确需承载的组件。寻求可读性和壁纸清晰度的平衡；不额外强制模糊整张壁纸。消除上下亮条、非预期接缝和裁切，保留对输入框外侧黑色底衬的修复。
- 壁纸装饰层不接收指针输入；壁纸自身控件可操作。保留 Codex 界面组件的位置、原生标题栏定位、窗口拖动、窗口控制与可访问的交互状态。不得用全局抬高层级、禁用拖拽或转发点击规避故障。
- 沿用已有素材、设置、快捷键和启停清理。停用移除壁纸与样式，恢复时从已加载的候选运行时挂载同一版适配，保留用户选择；临时替换页内样式不算正式加载。维持版本、主界面目标核验和单次挂载保护；不匹配时保持原界面。
- 「变更」优先沿用已核验的同一主窗口入口和现有防闪路径，不为视觉统一复制播放器或扩大目标范围。如果宿主更新导致结构出现实质变化，先取得新证据。无法安全做到透明的宿主区域，保留其原有读底和操作，并记录受限区域、原因与实际差异；不得修改受保护安装文件或改写内嵌网页、编辑器内容。

## Testing Decisions

只使用已确认的两层：现有浏览器夹具覆盖可稳定复现的行为，真实 Codex 覆盖宿主交互和实际画面。不新增测试架构或像素快照基线。优先在既有注入入口、浏览器鼠标与键盘输入及公开运行时状态上验证可观察结果；命中或计算样式只在能直接说明实际回归时使用。复用已有启停、工具交互和「变更」夹具，避免重复用例、样式字符串或固定透明度断言，也不为测试增加生产兜底、重试或私有接口。真实宿主不得用程序触发点击代替鼠标。

- [x] **源码实现与复查：**确认整套材质集中管理；原有布局、主题、监测与清理机制保持；已知顶栏定位、防闪和输入区修复没有回退；记录不能安全透明化的宿主区域。
- [x] **自动回归：**复用现有夹具，验证代表性顶部及壁纸控件点击产生可见响应，输入框可聚焦并接收键盘输入、输入框外侧无大底衬，以及停用清理、重新启用后恢复候选视觉与选材。按真实回归补齐缺口，不重复已有用例。
- [ ] **实际加载：**在后续获准的验收中，核对专用实例的 Codex 版本、主界面目标与实际生效的候选版本；如需冷启动，由用户通过专用入口手动执行。核对启停后仍是同版适配，不能用临时样式、旧回执或工作树版本替代。
- [ ] **真实操作：**用鼠标验证顶部目录与聊天标题下拉、文件和「变更」标签、可安全测试的顶部按钮、原生空白区域拖动及窗口控制；验证输入、滚动、文本选择、工具行展开、侧栏及右侧面板开合、壁纸控件。在现场复发时记录点击位置、实际命中和可见结果；不发送聊天，不提交外部操作，不关闭有未保存内容的标签。
- [ ] **真实视觉：**使用明亮、深色、细节复杂的代表性壁纸，覆盖 Codex 明暗主题以及至少常规与较窄窗口尺寸，在聊天和右侧面板开合等状态下亲自查看当前脱敏截图。检查字体与状态对比、壁纸主体、上下边缘、接缝、裁切、遮挡、输入区黑块、重复读底和非预期模糊。记录样本、主题、尺寸、面板状态及未覆盖组合。
- [ ] **真实启停与切换：**从已有壁纸库选择并切换代表素材；使用真实键盘执行 `Alt+Shift+W` 停用与恢复，核对原生外观、当前素材、设置和候选样式均正常。用真实界面连续完成至少十轮「聊天 → 变更 → 返回」，录屏并亲自复看操作时序，检查黑闪、亮暗跳变、默认背景闪入、旧新画面交替和布局跳动。仅开合摘要面板不计轮次；静态截图、DOM 或播放器计数不能代替录屏。
- [ ] **用户确认：**提交同版候选的脱敏截图、录屏检查结果及剩余限制，由用户确认实际视觉效果。分别记录源码实现、自动测试、当前实例实际加载、真实视觉、真实端到端及用户确认；缺证据的项保留待验。

## Out of Scope

- 不新增播放器、素材格式、联网壁纸能力或壁纸挂件；不重做 Codex 布局或交互。
- 不修改受保护安装文件，不启用 Windows 登录自启动，不实现原入口自动接入或未经核验的其他窗口注入。
- 八小时基础验收、七天日常观察及其他长期稳定性门禁继续独立记录，不由本规格代替。
