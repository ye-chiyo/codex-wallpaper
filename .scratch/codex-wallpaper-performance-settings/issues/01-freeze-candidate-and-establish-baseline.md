# 01: 冻结当前候选并建立性能基线、预算

**What to build:** 在开始任何优化前，冻结当前工作树候选并建立可重复的性能基线。先记录实际运行时、生成样式、Codex 版本、主界面目标、代表素材、窗口与主题，再覆盖壁纸停用与现有实现的同条件对照，以及静态图片、代表性视频、Scene、设置打开/关闭/连续调节、切换、不可见恢复和停用恢复。基线要区分稳定播放、首次加载峰值、连续切换、设置交互和暂停恢复，并给出确认的瓶颈、未确认假设和不可测项。优化前还必须固定资源、交互时延、停用回落、重复切换内存趋势和隐藏时活动预算，不能只交建议。

**Blocked by:** 无，可直接开始。

**Status:** ready-for-human

**Reuse boundary:** 复用现有专用入口、只读探针、浏览器夹具、公开运行时状态和已有采样能力；不新增常驻监控服务，不安装大型测试框架。

**Human action:** 如当前实例不是同版候选，用户需要保存工作并从专用入口干净启动；不得启用 Windows 登录自启动。

- [x] 记录当前候选的运行时与生成样式指纹、Codex 包版本、主界面目标、代表素材、窗口尺寸、主题、可见状态和采样工具。
- [x] 用相同素材与操作序列完成壁纸停用、现有实现的对照，并分别测试代表性静态图片、视频、Scene、设置打开/关闭/连续调节、快速切换、不可见恢复和停用恢复；现有素材库没有原生离线 Web。
- [x] 主要场景先预热，默认采样 60 秒并重复 3 次；记录原始采样、波动、计量口径及无法获取的指标，说明共享进程成本的归因边界。
- [x] 在优化前固定资源改善目标、输入与面板响应预算、停用回落、重复切换内存趋势和隐藏时活动预算，写明依据与波动阈值；后续不得静默放宽。
- [x] 汇总已确认瓶颈、未确认假设和不可测项，明确后续优化只能从已确认命中项中选择；本单不修改业务代码。
