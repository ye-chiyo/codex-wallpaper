# Codex 壁纸性能优化与设置面板完善

**Status:** ready-for-agent

**更新日期：** 2026-11-18

**实施状态：** 三页设置与控件修复已进入本地候选，真实 Codex 冷启动、同候选功能性能与用户视觉验收待完成。

**已确认的测试边界：** 现有浏览器行为回归＋真实 Codex 性能测量。执行 agent 负责代码改造、功能回归与性能验收；用户负责视觉与审美验收。

## Problem Statement

用户反馈，启用主界面壁纸后资源占用较大，Codex 运行速度下降。目前尚未用可重复的同条件对照，确认视频解码、Scene 渲染、界面合成、素材传输、设置更新和资源清理各自的开销。

壁纸工具自己的设置面板只提供少量参数，缺少清晰分组、性能控制及全局与分区外观调节。用户希望参考原项目的设置方案，在保留已确认界面风格的前提下获得更完整、真正生效的控制能力。本次不是重新设计 Codex 原生设置页。

截至本轮只读检查，当前本地实现包含以下值得测量的路径，但不能据此认定卡顿根因：

- 视频由媒体元素解码，再通过绘制循环呈现到 Canvas；绘制帧率上限不等于整个解码链已经降载。
- 设置滑块在输入期间保存配置，部分分支重复保存；跨窗口配置事件会重新应用当前素材。
- 设置面板重绘时重建素材卡片和调节控件，需要区分必要刷新与重复工作。
- 素材按需分块传输，切换时存在新旧素材准备与交接过程，需要观察瞬时峰值及旧资源释放。

这些是当前磁盘代码的观察，不是已加载版本或真实运行证据。执行会话开始时须重新核对版本及现有改动。

## Solution

按“建立性能基线 → 修复已证实瓶颈 → 完善设置和配置更新 → 同一候选功能与性能验收 → 交用户视觉验收”的顺序推进。

性能优化优先减少不必要的解码、绘制、重复初始化、过期加载和资源残留。不同素材采用与其实际能力匹配的策略，不以统一的帧率标签掩盖不同播放器的差异。

设置面板沿用已经确认的半透明界面风格，保留统一的「壁纸设置」入口。2026-11-18 决定用顶部页签替换原四个纵向区域，每次显示一个独立页面。

| 页面       | 能力                                                                       |
| ---------- | -------------------------------------------------------------------------- |
| 壁纸库     | 搜索、类型和收藏筛选、导入与选择素材、加载与兼容状态                       |
| 播放与性能 | 静音、音量、适用的帧率上限、性能档位、后台暂停策略和轮播                   |
| 外观与预设 | 暗化、模糊、不透明度、画面适配、界面读底、分区样式、预设导入导出和恢复默认 |

切页保留素材选择、库筛选和已输入的调节值，提交尚未写盘的设置，继续使用当前播放器。分区覆盖折叠在外观常用项之后。参考固定版本 DSH 的互斥页签、常用与高级分层及共用配置定义，沿用 Codex 壁纸面板的原有组件、主题变量与保护。

### 职责与完成状态

| 工作                                             | 负责人     | 完成证据                             |
| ------------------------------------------------ | ---------- | ------------------------------------ |
| 基线、瓶颈定位、优化及预算对照                   | 执行 agent | 可复现步骤、原始采样、前后对照及限制 |
| 设置界面与配置链代码改造                         | 执行 agent | 已确认规格的实现、有效控件及行为回归 |
| 真实功能路径与性能验收                           | 执行 agent | 已加载候选的实际操作、资源与响应结果 |
| 界面是否美观、壁纸是否清晰、层次与透明度是否满意 | 用户       | 对明确候选版本的反馈与确认           |

执行 agent 仍须检查控件能否点击、键盘能否操作、内容能否滚动到达等功能问题，但不承担截图审美评审、逐帧美观审查或代替用户确认视觉效果。自动化几何或行为断言不能代表视觉通过。

代码与性能完成后可交付“待用户视觉验收”候选。视觉等待不阻塞其他独立工程工作，也不允许提前将整项规格标成完成。

## User Stories

1. 作为用户，我希望启用壁纸后输入和滚动仍然流畅，以便正常使用 Codex。
2. 作为用户，我希望性能优化基于真实瓶颈，以免修改无关路径却没有改善。
3. 作为用户，我希望快速选择性能优先或均衡档，以便平衡效果和开销。
4. 作为用户，我希望看到档位实际修改的参数，以便理解取舍。
5. 作为用户，我希望只操作当前素材真正支持的参数，以免遇到无效控件。
6. 作为用户，我希望不可见时暂停动态壁纸，以减少无意义消耗。
7. 作为用户，我希望恢复可见后自动继续，以免重新选择素材。
8. 作为用户，我希望停用后释放播放器和待加载任务，以恢复工作流畅度。
9. 作为用户，我希望静态图片稳定显示后不持续绘制，以减少资源占用。
10. 作为用户，我希望快速连续切换时只有最后一次选择生效，以免旧画面回流。
11. 作为用户，我希望正式首帧准备好后再交接，以避免缩略图放大、模糊和构图跳变。
12. 作为用户，我希望加载失败保留已有画面并解释原因，以便继续使用。
13. 作为用户，我希望调整外观或音量时不重新加载壁纸，以保持操作连续。
14. 作为用户，我希望设置面板沿用现有风格并清晰分组，以便找到需要的功能。
15. 作为用户，我希望通过搜索、类型及收藏查找素材，以便管理本地壁纸。
16. 作为用户，我希望区分原生播放、预览降级、加载中与失败，以了解实际状态。
17. 作为用户，我希望常用项和高级项分层，以免大量参数挤在一起。
18. 作为用户，我希望分别调节壁纸画面和界面读底，以兼顾欣赏和阅读。
19. 作为用户，我希望分区默认继承全局参数，并可单独覆盖和恢复继承，以减少重复配置。
20. 作为用户，我希望设置在明暗主题和窄窗口中仍可操作，以适应日常布局。
21. 作为用户，我希望查看参数数值并通过滑块、数值输入及键盘调整，以便精确设置。
22. 作为用户，我希望设置即时预览并可靠保存，以免重新打开后丢失。
23. 作为用户，我希望升级保留已有设置、收藏和轮播，以免重新整理。
24. 作为用户，我希望保存外观预设并导入导出，以便复用喜欢的组合。
25. 作为用户，我希望导出不携带聊天、凭据、素材文件和个人路径，以便安全备份。
26. 作为用户，我希望恢复一组默认值不会删除壁纸或收藏，以免误操作。
27. 作为用户，我希望多窗口同步设置不触发不必要的素材重载，以保持稳定。
28. 作为用户，我希望由执行 agent 提供性能数据和可操作候选，由我判断最终视觉效果，以保持清晰分工。
29. 作为用户，我希望诊断工具仅在必要时运行，以免监测本身成为新负担。

## Implementation Decisions

### 1. 基线先于优化，预算先于结果

执行会话先确认工作树、版本、待保留改动及实际加载候选。建立相同素材、窗口尺寸、主题、可见性与操作序列下的对照：壁纸停用、现有实现、优化候选。

至少覆盖静态图片、代表性视频、代表性 Scene、设置打开/关闭/连续调节、切换、停用恢复及不可见恢复。可运行的离线 Web 单独记录，不能用预览图代替原生播放测量。

基线完成后，执行 agent 将具体预算和依据记录到验收材料，再开始优化。日常工程预算由 agent 根据实测制定，无需逐项重新请求确认；涉及降低已确认画质默认值、取消功能或扩大范围的取舍才交用户决定。不得在结果不达标后悄悄放宽预算。

### 2. 按素材类型最小改造

- 视频：测量解码、Canvas 绘制与合成开销，再评估能否减少中间处理；不预先承诺更换播放器。FPS 控制须说明约束的是绘制还是实际媒体处理。
- Scene：优先复用已安装引擎的暂停、帧率及可用质量接口；接口不足时说明能力边界，不伪造质量档。
- 图片：稳定显示后无需持续媒体绘制循环。
- Web：不能把父页面限帧等同于 iframe 内部限帧；不能用只隐藏元素冒充暂停。当前安全播放与生命周期能力不足时保留明确限制。
- 素材传输与缓存：仅在证据表明其构成瓶颈时修改。不得默认引入转码服务、复杂缓存、新服务器或引擎 fork。

停用、不可见和新素材准备分别处理。保留同一尺寸和裁切下的首帧交接；允许必要的短时准备，但不长期保留两个活动播放器。失效任务停止继续消耗资源，所有类型都遵守最新选择生效和停用后不能复活。

### 3. 让设置更新只影响相关行为

区分外观、播放参数、轮播计划和素材身份变化。外观、音量及支持原位修改的参数不得无故重新加载素材。

连续输入即时预览；持久化和跨窗口同步合并冗余更新，保证最终值可靠落盘。复用现有配置、事件和同步入口，不建立平行状态机或第二套存储。

检查面板重建、缩略图请求和素材缓存的实际成本。只对测得的热点做局部刷新或按需处理，不提前引入复杂列表虚拟化或通用状态框架。

### 4. 设置能力边界

本轮必要能力：

- 壁纸库搜索、类型筛选、收藏、当前选择和明确的加载/兼容状态。
- 静音、音量、轮播，以及性能优先/均衡/自定义档位。保留现有默认 30 FPS 方向，不自动开启高帧率或更高特效。
- 对实际支持的播放器提供有效帧率和渲染质量控制；图片等不适用类型不显示虚假的 FPS 效果。
- 壁纸暗化、模糊、不透明度，以及支持类型的保持比例填充和完整显示。
- 全局读底、必要的细边框和有限界面雾化，支持聊天、侧栏/顶部、右侧面板和设置面板的必要局部覆盖。
- 分组默认值、外观预设保存及设置导入导出。

性能优先档采用明确参数组合并展示取舍；不得靠静默换图或预览降级冒充优化。尚无可靠接口的高级质量项可以明确列为不支持，不得呈现可拖动但无效果的控件。

### 5. 参数语义与 UI 改造

壁纸模糊和界面雾化分开，壁纸不透明度和面板读底分开，设置帧率和实测帧率分开。没有可靠观测能力时不展示假实时数字。

分区默认继承全局，覆盖状态和恢复继承入口明确；避免同一效果由多个不相关滑块重复控制。选择预设后用户调整参数，状态变为自定义。

执行 agent 依据既有视觉规范实现统一控件、分组、主题适配和响应式行为；不另启多轮设计方案，不擅自新增风格。用户完成审美与最终视觉判断。

设置面板可滚动、键盘可到达，标签与数值说明完整。原生顶部定位、点击、窗口拖动和 Codex 组件操作保持正常。

### 6. 上游复用范围

| 能力                         | 处理方式                                  |
| ---------------------------- | ----------------------------------------- |
| 本地素材扫描与识别           | 继续使用现有已引入实现                    |
| Scene 渲染                   | 继续使用现有引擎，核验实际安装版本的接口  |
| 设置分组、默认值、参数语义   | 参考上游并筛选适合 Codex 的部分           |
| 全局继承与局部覆盖           | 借鉴模型，接入现有配置链                  |
| 设置 UI                      | 复用项目现有控件与主题，不搬 DSH 页面结构 |
| 宿主保存、注入、窗口生命周期 | 沿用 Codex 现有适配，不引入 DSH 宿主依赖  |
| 转码、系统音频、桌宠与特效   | 本轮不引入                                |

参考固定上游版本，不因设置改造顺带升级整套依赖。复用第三方实现时保留必要来源和许可声明。

### 7. 持久化与预设

缺失字段使用默认值，保留既有收藏、轮播和素材选择。仅对实际需要的结构变化做小范围迁移。

预设导出仅携带约定的外观与播放参数，不包含素材、个人路径、聊天或凭据。导入校验版本、结构及数值范围；失败不改变现有设置。配置结构由一处维护，不建立相互漂移的手写字段清单。

恢复一组默认、恢复全部设置和移除素材必须语义不同。不得在恢复外观时删除用户素材及收藏。

## Testing Decisions

### 已确认的测试边界与负责人

1. 现有浏览器行为回归：执行 agent 负责，复用浏览器夹具、素材加载测试和公开运行时入口。
2. 真实 Codex 性能与功能路径：执行 agent 负责，对实际加载的同一候选记录证据。
3. 视觉与审美验收：用户负责。agent 提供候选标识、变更说明和简短检查步骤，不代用户勾选视觉通过。

不新增大型测试框架。测试用户可观察结果，不镜像内部实现；仅在实际必要时用已有低层边界补充定位。截图数量、CSS 字符串和函数调用次数不能替代业务验收。

### 自动行为回归

- 修改外观和音量不重载当前素材；参数作用范围正确。
- 参数保存、面板重新打开、旧配置读取和分区继承/覆盖正常。
- 配置导出、导入、实际应用、重新打开组成完整闭环；失败保留旧值。
- 快速选择只提交最后一次；失败保留旧画面；停用取消待加载任务。
- 可见性恢复不会累积绘制循环、事件监听或播放实例。
- 设置搜索、筛选、键盘操作及恢复默认不损坏素材库、收藏和轮播。
- 不支持的参数有明确状态，不产生假成功。

对同一实际回归避免重复写多层镜像测试；保留能防止已有严重问题复发的覆盖。

### 真实性能测量方法

- 记录硬件环境、Codex 包版本、代码版本、素材类型/尺寸/帧率、窗口和主题、前后台状态及采样工具。
- 稳态测试先预热；默认每个主要场景采样 60 秒、重复 3 次。基线波动明显时调整窗口并记录理由，不机械重复全部测试。
- 将稳定播放、首次加载峰值、连续切换、设置交互和暂停恢复分开测量。
- 汇总相关进程 CPU、工作集/可用的专用内存、可获取的 GPU 解码/合成指标，以及可观察的输入/面板响应时延。说明计量口径；共享 GPU 进程不全部归因于壁纸。
- 缺少指标或采样权限时标记不可测，不填零，不用单个瞬时截图得出资源改善结论。
- 输入测试使用临时无敏感文本且不发送，保护并恢复原有草稿。隔离模型生成、网络等待等无关负载；无法隔离时记录其影响。
- 基线阶段固定重负载代表素材的资源改善目标、交互响应预算、停用回落、重复切换后内存趋势和隐藏时活动预算，再做优化。
- 改善必须超过测量波动；同等画质对照与降低质量后的节能结果分开报告，不以画质下降替代同条件优化证据。
- 不以操作系统工作集没有立即缩小直接认定泄漏；结合持续增长趋势、活动任务和资源生命周期判断。
- 诊断和采样仅在需要时开启，验收后关闭，不安装常驻高频监控。

### 真实端到端路径

通过实际 UI 完成：打开设置、搜索素材、选择播放、调整性能与外观、保存预设、导出并导入、关闭再打开设置、停用并恢复。

检查顶部控件、键盘、输入滚动、面板开合及至少十次“聊天 → 变更 → 返回”的功能与性能稳定性。检查多窗口同步时按页面解释实例数，不将一个视频及其呈现 Canvas 当作两个独立播放器。

明暗主题和宽窄窗口检查中，agent 负责控件可到达、可点击、可输入、内容可滚动等功能表现。文字观感、透明度、画面清晰度、闪动的视觉感知及整体美观由用户确认；不得要求 agent 通过逐帧审美审查完成本规格。

代码热加载不等于正式冷启动验证。需要退出、重启、冷启动或其他中断操作时由用户安排。缺少此类证据时保留待验，不用旧实例数据填补。

### 验收清单

**执行 agent 负责：**

- [ ] 已建立可重复性能基线，并区分确认的瓶颈与待验证假设。
- [ ] 优化达到修改前固定的资源与响应预算，证据对应最终候选。
- [ ] 设置功能按规格实现，所有可用参数具有实际效果。
- [ ] 配置保存、同步、旧值保留、继承和预设导入导出通过行为回归。
- [ ] 切换、取消、失败恢复、暂停及停用清理通过回归，无已知功能阻塞。
