# Windows Codex 主界面壁纸移植

**Status:** ready-for-agent

## Problem Statement

我希望在 Windows 上日常使用 Codex 时，能把原项目的壁纸体验放进主聊天界面。壁纸需要和已有工具卡片、代码、输入框及面板共存；切换聊天或恢复使用后无需重新发指令。我还需要保留现有账号、聊天和原入口，在故障或版本更新时能快速恢复普通 Codex。

## Solution

以 dsh-wallpaper-engine 为原型，复用可脱离 DSH 的素材与播放能力，重新适配 Codex 主界面、全局设置、窗口生命周期及维护方式。先交付一个可撤销的静态背景验证，再逐步交付界面适配、动态播放、四类素材和日常管理。首版范围是当前用户的 Windows Codex 自用。

## User Stories

1. 作为 Codex 用户，我希望壁纸显示在真实聊天主界面里，以便边工作边看到它。
2. 作为 Codex 用户，我希望启用壁纸后仍使用原账号和同一个已有聊天，以便延续当前工作。
3. 作为 Codex 用户，我希望原 Codex 入口保持可用，并验证从该入口打开后能否自动生效，以便维持现有启动习惯。
4. 作为 Codex 用户，我希望不用开终端或发指令即可加载壁纸，以便每天直接使用。
5. 作为 Codex 用户，我希望能阅读流式回复和长聊天，以便不受壁纸干扰。
6. 作为 Codex 用户，我希望工具卡片能正常展开、折叠和滚动，以便查看工具结果。
7. 作为 Codex 用户，我希望代码和差异有足够实底，复制、文本选择和输入快捷键保持可用，以便继续写代码。
8. 作为 Codex 用户，我希望文件、浏览器和终端面板保持原有操作，以便并行查看工作内容。
9. 作为 Codex 用户，我希望弹窗焦点、设置与侧栏正常，以便通过鼠标和键盘完成日常操作。
10. 作为 Codex 用户，我希望壁纸适配明暗主题、窗口与应用缩放及不同 DPI，以便改变布局后依然可读。
11. 作为 Codex 用户，我希望切换聊天或项目、长时间不发消息时仍有壁纸，以便脱离当前聊天和模型回合使用。
12. 作为 Codex 用户，我希望最小化或不可见时暂停，恢复可见或休眠唤醒后继续，以便节省资源。
13. 作为 Codex 用户，我希望不同窗口共享壁纸设置但独立暂停，以便只在可见窗口播放。
14. 作为 Codex 用户，我希望导入本地图片和视频并重开恢复，以便使用自己的素材。
15. 作为 Codex 用户，我希望浏览本机已下载的 Wallpaper Engine 壁纸，以便利用已有库存。
16. 作为 Codex 用户，我希望播放可兼容的 Scene，并看清降级或不支持的原因，以便决定如何使用素材。
17. 作为 Codex 用户，我希望离线 Web 壁纸可用，联网只在我主动允许后发生，以便掌控网络访问。
18. 作为 Codex 用户，我希望壁纸互动不抢占点击、滚动或键盘，以便在同一窗口继续工作。
19. 作为 Codex 用户，我希望素材库、设置和核心播放断网可用，素材缺失时跳过并提示，以便本地使用不被中断。
20. 作为 Codex 用户，我希望可视化浏览、导入、切换、收藏和建立播放列表，以便无需模型参与。
21. 作为 Codex 用户，我希望设置定时轮播并在重开时保留配置，以便日常自动更换壁纸。
22. 作为 Codex 用户，我希望调节暗化、模糊、透明度和帧率，以便在通透与易读之间选择。
23. 作为 Codex 用户，我希望默认静音、需要时才开启声音，以便不影响工作。
24. 作为 Codex 用户，我希望一键停用并能卸载，以便随时恢复原界面和原入口。
25. 作为 Codex 用户，我希望播放故障、辅助程序退出或 Codex 更新不兼容时仍能继续工作，以便安全恢复。
26. 作为 Codex 用户，我希望看到实际的资源、恢复和长期观察记录，以便决定是否把适配用于日常工作。

## Implementation Decisions

- P1 复用本仓库已通过专用入口 P0b 的启动器与只读核验，针对已验收的 Windows MSIX 版本和真实主界面验证单一静态渐变、即时停用和重开恢复。版本或目标不匹配时不应用适配。既有探针仍用于只读核验。
- 保留原入口、官方包和日常 profile。不新建空白 profile，不修改受保护安装文件，不读或迁移登录凭据与聊天。现有工作实例不作为自动启动、退出或重启的目标。
- 适配 Codex 原有界面组件和主题，保留布局与操作；复杂表面保留实底。DSH 的宿主服务、slots、组件注册及资源清理不直接搬入。
- 固定上游版本，先核实素材清单、元数据、媒体准备、选择、轮播和设置迁移能否独立复用；Scene/Web 的渲染器及播放桥逐类验收。保留源代码许可声明，媒体和字体单独核对来源。
- 单机全局设置跨项目、聊天和窗口一致。播放与可见性按窗口处理，默认前台最高 30 FPS 且静音；不可见暂停，恢复可见或唤醒后继续，完全退出 Codex 后允许停止。
- 本地素材、设置和核心播放可离线；不上传壁纸、聊天或本机路径，不依赖付费服务，不自动订阅或下载创意工坊。Web 壁纸联网默认拒绝，须明确允许；无法隔离就不启用。
- 播放失败优先降级或停用，保持 Codex 可用。即时停用移除适配的节点、样式和播放资源；彻底撤销时正常退出专用实例，再用原入口启动并核对旧调试监听已关闭。卸载只处理本项目新增内容。
- 任务 13 与 P1 并行，未验证原入口自动生效时不把专用入口算作满足该要求。基础验收需 12 完成，且 13 实测通过，或用户明确接受专用入口用于该候选版本的验收。

## Testing Decisions

1. **离线边界：**优先复用启动器的 preflight、启动候选去重和只读探针的测试方法。P1 在适配入口验证可观测行为：不匹配时保持原界面、重复应用只有一层、停用清理、重开保持停用。离线检查不启动或连接真实 Codex。
2. **真实宿主边界：**由用户选择空闲时段手动验证冷启动、原账号与同一个聊天、原入口对照和撤销；以后在同一真实宿主验证明暗主题、工具卡片、面板、输入与各类壁纸。离线测试和独立预览不替代人工结果。
3. **资源与恢复：**同一组操作下对照原版、静态和动态的 CPU、GPU、内存、帧率及交互响应。先做短测并确认本机预算及恢复时限，再进入 8 小时与 7 天门槛。素材播放逐类记录原生、降级或不支持。
4. **证据记录：**分别记录源码、候选版本、实际部署和运行版本。诊断只记必要的版本、窗口/播放器计数、失败和恢复信息，不记录聊天正文、凭据或完整文件列表。人工项取得证据后再勾选。

## Out of Scope

- P1 不做播放器、素材库、Web 壁纸、工具卡片与面板全面适配，或长期稳定验收。
- 首版不移植原项目自带挂件，不改造 Codex 布局，不承诺整个创意工坊兼容。
- 不做项目或聊天单独配置，不做跨平台或公开分发；系统音频频谱与正在播放联动留到长期观察通过后。
- 本次工作只发布规格与任务，不授权编写实现或操作 Codex。
