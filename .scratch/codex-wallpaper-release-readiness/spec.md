# Codex 壁纸发布就绪验收与失败路径收敛

**Status:** ready-for-agent

## Problem Statement

当前工作树的 Node 全量套件 73/73 通过，四个 PowerShell 启动器套件也通过，但这些结果主要来自 headless Edge、fake CDP、合成的 Codex 页面夹具和启动器预检 stub。它们还不能回答用户真正关心的问题：当前 `13620f8` 是否能在真实 Codex 中完成主界面壁纸冷启动、复用、切换、停用恢复和清理。

同时，交付契约存在以下缺口：

- 启动器代码支持 `26.1117.4957.0` 和可信未登记版本，根 README 与发布说明仍只声明两个旧版本。
- README 提到同源页面设置同步和待验的多窗口，但监督器只接受唯一精确主页面；现有“跨窗口”测试实际只用一个隐藏 iframe 触发 `localStorage` 事件。
- Scene 测试主要注入 fake `WebWallGL`，没有证明真实 `webwallgl@3.0.0` 和 Workshop Scene 能工作。
- 清除数据的多窗口协调使用固定 250 毫秒等待；清除成功路径没有明确清空运行时素材缓存。
- 已提交视频之后发生的播放错误、Web iframe 永不触发 load、IndexedDB 失败没有完整用户可见降级。
- `pnpm test` 只运行 Node 套件；PowerShell 启动器测试只在 CI 工作流中单独运行，开发者按 README 执行本地测试时会漏掉启动器路径。

这些问题不应通过把所有状态都标成“已通过”来解决。发布就绪必须分别记录源码、自动回归、真实 Codex 端到端、用户视觉确认和长期稳定性。

## Solution

把当前工作树收敛为一个可以明确判断是否可发布的候选版本：

1. 固定当前源码 SHA，在真实 Codex 中执行一次由用户控制的完整主界面壁纸验收，记录真实回执、运行层身份和用户可见结果。
2. 以启动器的实际行为为准，统一精确版本、可信未登记版本和失败回退的用户文档；不让代码、README、发布说明和测试各自维护不同版本表。
3. 明确发布边界为单一已验证 Codex 主窗口。保留精确 target 核验和失败关闭；同源 `storage` 只作为已注入页面的设置同步，不再宣称第二个真实主窗口必定被加载。
4. 增加真实 `webwallgl@3.0.0` 和真实离线 Web iframe 的集成覆盖；替身只能证明运行时接线，不能证明生产渲染器或隔离行为。
5. 收敛清理、错误恢复和测试门禁：用可确认的 reset 协议替代固定等待，清空运行时缓存，补齐 late-error 和超时降级，并把 Node 与启动器测试纳入一个明确入口。

## User Stories

1. 作为 Codex 用户，我希望从专用入口打开当前候选后看到上次保存的主界面壁纸，以便日常使用不需要重复设置。
2. 作为 Codex 用户，我希望专用入口只接入经过包、摘要、profile、监听和主页面核验的实例，以便不匹配时继续使用原 Codex 界面。
3. 作为 Codex 用户，我希望重复运行专用入口时复用已核验实例，以便不产生第二个壁纸层、宿主或玩家。
4. 作为 Codex 用户，我希望真实 Codex 中的当前素材、设置和快捷键行为与自动夹具描述一致，以便测试通过能说明实际业务可用。
5. 作为 Codex 用户，我希望在真实 Codex 中导入图片和视频后切换、退出重开和停用恢复都正常，以便不会因为版本更新丢失壁纸。
6. 作为 Codex 用户，我希望真实 Codex 的 Scene 由实际安装的 WebWallGL 渲染，而不是只通过替身测试，以便知道我的 Scene 是否真的能播放。
7. 作为 Codex 用户，我希望离线 Web 不执行脚本、不加载外链，并在加载失败或超时时显示明确降级，以便本地第三方页面不会破坏宿主。
8. 作为 Codex 用户，我希望同源配置在已经注入的页面之间同步，但不同窗口的可见性和暂停状态独立，以便理解哪些窗口实际有壁纸。
9. 作为 Codex 用户，我希望发布文档明确说明当前只支持一个已验证主窗口，以便不会把未支持的第二窗口当成故障。
10. 作为 Codex 用户，我希望安装的是 26.1117.4957.0 时，根 README、启动器和发布说明都告诉我同一兼容策略，以便不会误判“不支持”。
11. 作为 Codex 用户，我希望可信但未登记的版本只有通过完整身份和主界面探测后才接入，失败时保留原界面，以便更新不会静默绕过安全边界。
12. 作为 Codex 用户，我希望停用和清除操作在多个同源页面存在时不会因为固定等待时间而误报失败，以便清理结果可预测。
13. 作为 Codex 用户，我希望清除页面数据后重新启用时不会复用旧 Web 内容、旧失败状态或旧预览缓存，以便“清除”确实回到默认状态。
14. 作为 Codex 用户，我希望视频首帧之后发生解码错误时保留可读预览或明确提示，而不是停在黑画面。
15. 作为 Codex 用户，我希望 Web 壁纸加载超时后显示作者预览或静态降级，而不是永久停留在“加载中”。
16. 作为 Codex 用户，我希望宿主锁不会因为 PID 被其他进程复用而长期阻塞新的专用启动，以便恢复路径可靠。
17. 作为维护者，我希望版本、目标、锁和配置的单一来源可追踪，以便后续 Codex 更新时知道该改哪里。
18. 作为维护者，我希望测试明确区分真实 Codex E2E、真实浏览器集成、启动器集成和单元测试，以便不会被总通过数误导。
19. 作为维护者，我希望开发者用一条命令就能运行 Node 和 PowerShell 启动器测试，以便本地门禁与 CI 门禁一致。
20. 作为维护者，我希望测试只验证用户可观察行为，不依赖 fake engine、私有函数或易变 CSS 字符串，以便重构不会制造假失败。
21. 作为维护者，我希望测试输出的证据包含固定源码 SHA、候选身份、测试命令、结果和未覆盖场景，以便发布审查可复现。
22. 作为维护者，我希望当前未完成的 8 小时、7 天、真实登录、真实多窗口和全量创意工坊兼容继续明确列为边界，以便开发候选不会被包装成稳定版。
23. 作为用户，我希望视觉和审美仍由我本人确认，自动测试只证明功能、状态和可观察的交互结果。
24. 作为用户，我希望最终发布建议明确是“可发布”“有条件发布”还是“阻塞发布”，并列出未验证内容，以便决定是否继续使用当前候选。

## Implementation Decisions

### 发布候选与证据层级

- 以当前审核基线 `13620f8aded4d2d61a4a11a5a2a5fc25c22d8108` 固定候选；任何实现修复后的新 SHA 都需要重新标记受影响证据。
- 证据必须分层记录：单元/纯函数、PowerShell 启动器预检、启动监督器集成、headless Edge 浏览器夹具、真实桌面原生夹具、真实 Codex 页面端到端、用户视觉确认。高层通过不能替代低层缺口。
- 真实 Codex 验收必须由用户控制实例生命周期；agent 不关闭、不重启、不连接当前正在使用的 Codex，也不把只读状态查询当作注入成功。

### Codex 兼容性契约

- 精确哈希快速路径、可信未登记版本的运行时探测、未知/摘要漂移/非 OpenAI 签名/多主进程失败关闭继续作为同一策略。
- 交付文档必须列出当前已登记的精确版本，并明确“可信未登记版本会先探测主界面、失败保持原界面”；不能只保留旧版本表。
- 代码是兼容性行为的权威来源，README、发布说明和候选记录只描述同一事实。新增版本时同步更新文档和预检回归。

### 单主窗口边界

- 当前发布候选只支持一个经过验证的 Codex 主窗口；目标仍必须精确匹配 `app://-/index.html`，服务监听仍必须归当前主进程所有。
- 查询路由的辅助窗口继续被忽略；出现两个精确主页面时继续 fail closed，并给出明确、可诊断的结果。
- 同源 `storage` 监听只说明已注入页面之间的设置同步，不承诺启动器自动注入未来的第二个主窗口。多窗口壁纸实现另立任务，不属于本次发布就绪范围。

### Scene、Web 与素材生命周期

- Scene 集成测试必须加载实际 `webwallgl@3.0.0` 运行时，不允许通过赋值 fake `globalThis.WebWallGL` 证明生产路径。测试需要验证首帧、Canvas 尺寸、暂停/恢复、帧率、音量和 fit 能力；真实 Scene 素材必须使用可分发或用户授权、可复现且脱敏的 fixture。
- 离线 Web 使用真实 `iframe` 和 `srcdoc`，验证脚本、内联事件处理器和外部资源都不会执行或访问网络；无 load 事件时有有限超时和预览/静态降级。
- 图片、视频、Scene 和 Web 继续共享现有 stage、取消、代次隔离和提交 envelope；不得为测试或单次错误增加第二套播放器状态机。
- 已提交媒体之后发生的错误仍属于壁纸失败，必须有 late-error 处理，而不是因为首帧已经提交就永远忽略。

### 清理、失败恢复与运行时缓存

- 清除页面数据需要跨页面可确认的 reset 协议，而不是固定等待 250 毫秒。收到确认后再关闭数据库、删除 IndexedDB、移除运行时和写入禁用状态。
- 成功 reset 必须清空当前页面的运行时素材缓存、失败预览集合、失败素材集合、预览状态和待处理引用；不能只删除 IndexedDB 和 DOM。
- 宿主锁要么记录 PID 和进程创建时间并校验二者，要么把架构/发布文档改成实际只检查 PID 寿命。选择后必须新增 PID 复用、过期锁和无锁路径回归。
- 需要用户可见错误的 IndexedDB 导入、移除和 reset 失败必须写入运行状态；失败时保留当前素材和配置。

### 测试入口与交付门禁

- 保留串行 Node 测试以避免 CDP 端口争用，但新增一个明确的聚合入口，同时运行 Node 全量套件和四个 PowerShell 启动器套件。
- 原有 `pnpm test` 可以继续保留 Node-only 兼容入口，但 README 和发布检查必须使用聚合入口，避免开发者误以为只跑 Node 就完成启动器验收。
- Edge 路径、`ffmpeg.exe` 可选性和 PowerShell COM 依赖必须显式记录；条件跳过不能被描述成通过。
- 当前变更文件的 Prettier、`git diff --check` 和完整测试结果纳入交付记录；全仓既有格式问题不因本任务批量改写。

## Testing Decisions

### 测试原则

- 只测试用户可观察的结果、公开运行时 API、真实点击/键盘、页面计算样式、真实文件系统和真实进程状态；不断言私有变量、函数调用次数或完整 CSS 文本。
- 优先复用已有最高测试 seam：启动器公共 status/preflight、启动监督器/宿主进程、headless Edge 页面夹具和 native desktop fixture。尽量不增加第四种浏览器启动框架。
- 一个测试可以覆盖同一业务流中的多个断言；只有需要不同进程、失败状态或隔离环境时才启动新浏览器。
- 真实 Codex E2E 与自动测试必须分别记录；自动测试通过不能改变“真实 E2E 未完成”的状态。

### 三个自动测试 seam

1. **启动器公共行为 seam：** 使用 `Start-CodexWallpaper.ps1` 的 status、preflight、Startup 和 root-state 公共入口验证包身份、精确版本、可信未登记版本、主进程、profile、监听和启动失败结果。现有 `profile-preflight.test.ps1`、`startup-entry.test.ps1`、`startup-roots.test.ps1` 为 prior art。
2. **启动监督器/宿主 seam：** 使用真实 Node 子进程、真实宿主文件交付和受控 CDP fixture 验证唯一主页面、目标替换、锁、素材请求、Scene/Web 交付和清理。现有 `static-background.test.mjs` 的 supervisor/host 用例和 `wallpaper-host.test.mjs` 为 prior art。
3. **headless Edge 运行时 seam：** 使用真实浏览器、真实 DOM、真实 IndexedDB 和公开页面 API 验证素材切换、设置、可见性、重置、错误降级和跨页面同步。现有 `static-background.test.mjs` 的 headless Edge 用例为 prior art。

### 人工 E2E gate

- 由用户保存工作、完全退出 Codex 后从专用入口冷启动；agent 只提供命令、脱敏回执格式和检查清单，不操作当前实例。
- 必须覆盖：`Outcome: wallpaper-ready`、当前候选身份、主界面壁纸、图片/视频/Scene/Web、`Alt+Shift+S`、`Alt+Shift+W`、停用恢复、退出重开和双确认清理。
- 视觉、配色、排版、动画和截图不在 agent 自动验收范围；用户本人确认视觉结果。

## Out of Scope

- 不实现真正的第二主窗口自动注入、多窗口材质或跨窗口运行时；本次明确收敛为单主窗口。
- 不修改 Codex 安装包、原入口、登录凭据、账号或聊天正文。
- 不在本次任务中执行用户的真实退出、重启、启动或清理；T01 由用户独立执行。
- 不承诺 8 小时、7 天、全量创意工坊 Scene/Web 兼容或最低 Windows 版本。
- 不因为修复逻辑而重写整个运行时、播放器或测试框架。
- 不进行视觉审美判断，不批量格式化无关历史文件。
