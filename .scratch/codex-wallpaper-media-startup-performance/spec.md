# Codex 壁纸切换与启动体验优化

**Status:** ready-for-agent

**日期:** 2026-11-19

**实施状态:** 规格待实施。三项可行性探针已通过，完整运行时尚未改造。

**确认的测试主边界:** 真实 Codex 专用入口中的用户操作路径。现有浏览器夹具负责确定性行为回归，真实入口负责最终功能与性能验收。

2026-11-19 补充 [方案 A](../codex-wallpaper-plan-a/spec.md)。切换交互以方案 A 为准，悬停和仅按下均不准备视频。原有切换预算继续用于实测对照，启动任务继续按本规格跟踪。

## Problem Statement

用户在主界面使用壁纸时，发现同一张或相近体积的视频在 Codex 中切换明显慢于原项目 DSH Wallpaper Engine。代表性约 110 MiB 视频从点击到新画面出现约需 3.2 秒，现有大文件记录中曾出现 6 至 8 秒等待。视频被完整导入前，播放器无法开始读取，卡片还会短暂显示与实际能力不一致的状态。

壁纸随 Codex 启动恢复的速度也偏慢。现有成功回执从激活记录到接入完成通常为 5.4 至 10.2 秒，其中包含目标发现、多次 CDP 连接、重复素材扫描、隐藏面板构建和当前素材准备。启动过程还可能留下终端窗口或要求用户确认，并会把不属于首屏的完整壁纸库工作放进关键路径。

用户需要在保持 Codex 原界面可用、账号和聊天数据不变、版本不匹配时安全后退的前提下，获得接近原项目的切换和恢复体验。最终视觉观感由用户判断，执行 agent 只负责功能、性能、可操作性和证据。

## Solution

把视频接入从“完整文件通过 CDP Base64 导入后再创建播放器”改为“页面直接取得受限本地 File，并由原生播放器按需读取”。对 `moov` 位于文件尾部的 MP4，仅读取并修正小型索引区，再与 File slices 组合成虚拟媒体。对重复切换增加单槽元数据预热，并继续使用已有正式首帧交接。

启动改为单监督进程、单 CDP 会话和首屏优先恢复。Codex 尽快激活，接入前仍完成版本、目标与监听归属核验。启动关键路径只恢复当前壁纸和必要界面，壁纸库、完整设置面板、非当前预览和昂贵复核在首屏后或用户首次打开时执行。素材目录使用版本化持久索引和 stale-while-revalidate。

实施必须遵循三项工程门禁。

1. 代码保持最小、直接和可维护。重复状态、平行抽象、复杂算法和猜测性兜底必须先用证据证明必要。
2. 测试只保护有意义的用户行为或真实回归。不得为了覆盖率写内部实现镜像、重复断言或永远无法失败的空测试。
3. 充分复用项目已有的运行时、宿主、扫描、控件、配置、测试夹具和工具函数。新增实现前必须说明现有能力为什么不足。

## User Stories

1. 作为 Codex 用户，我希望点击壁纸后立刻看到明确的选中反馈，以便知道操作已被接受。
2. 作为 Codex 用户，我希望新素材准备好之前继续看到旧壁纸，以免切换时黑屏或跳回普通背景。
3. 作为 Codex 用户，我希望大型视频不必完整导入才开始解码，以便明显缩短切换等待。
4. 作为 Codex 用户，我希望首次看到的新画面使用正确尺寸和裁切，以免缩略图放大或构图跳变。
5. 作为 Codex 用户，我希望 `moov` 位于文件前部或尾部的 MP4 都能正常播放，以便覆盖不同作者导出的素材。
6. 作为 Codex 用户，我希望快速连续点击多个素材时只显示最后选择，以免旧请求晚到并覆盖新画面。
7. 作为 Codex 用户，我希望重复选择已经预热或播放过的素材时直接复用准备结果，以减少重复启动成本。
8. 作为 Codex 用户，我希望悬停或按下只预热一张候选视频，以免浏览器后台同时解码大量素材。
9. 作为 Codex 用户，我希望切换失败时旧壁纸保持可见并出现明确原因，以便继续使用 Codex。
10. 作为 Codex 用户，我希望切换中停用壁纸会立即取消读取、预热和播放器，以免停用后资源重新复活。
11. 作为 Codex 用户，我希望卡片的“加载中”“可播放”“失败”和“预览降级”状态反映实际能力，以免状态自相矛盾。
12. 作为 Codex 用户，我希望启动时先恢复当前壁纸，再在后台准备完整素材库，以便聊天界面不必等待所有管理功能。
13. 作为 Codex 用户，我希望有效缓存下快速恢复上次壁纸，以免每次开机都重复完整扫描。
14. 作为 Codex 用户，我希望无缓存首次启动时仍能先进入 Codex 并渐进加载，以免素材扫描阻塞主窗口。
15. 作为 Codex 用户，我希望缓存损坏、过期或库目录变化时自动回退到完整扫描，并使用最新结果。
16. 作为 Codex 用户，我希望素材扫描更新期间继续保留上一份可用索引，以免界面突然清空。
17. 作为 Codex 用户，我希望已经运行的专用实例再次启动时直接聚焦原窗口，以免创建第二个主进程或重复注入。
18. 作为 Codex 用户，我希望普通入口和登录入口成功启动时没有控制台窗口或回车确认。
19. 作为 Codex 用户，我希望失败的启动安全回退到原生 Codex 界面，并保留可诊断回执。
20. 作为 Codex 用户，我希望启动时的版本、进程、profile、目标页面和监听归属保护保持有效，以免连接到错误实例。
21. 作为 Codex 用户，我希望壁纸库和设置面板第一次打开时保持可用，即使它们在启动时被延迟构建。
22. 作为 Codex 用户，我希望导入素材的 Blob 只在真正需要时读取，以免无关大文件拖慢启动。
23. 作为 Codex 用户，我希望非当前素材的缩略图不在启动时批量请求，以减少首屏 I/O 和内存。
24. 作为 Codex 用户，我希望启动和切换优化不改变已有收藏、轮播、播放参数和外观设置。
25. 作为 Codex 用户，我希望新缓存结构可以安全升级，旧配置不会被丢弃或被错误兼容信息覆盖。
26. 作为 Codex 用户，我希望播放器、快捷启停和可见性恢复继续工作，以免性能改造破坏已有能力。
27. 作为 Codex 用户，我希望优化后的画面、主题和交互仍由我本人判断是否满意，以免自动化或执行 agent 代替视觉验收。
28. 作为 Codex 用户，我希望执行 agent 使用真实专用入口和真实素材提供可复现性能证据，而不是仅凭单元测试宣称体验改善。
29. 作为 Codex 用户，我希望切换和启动指标绑定当前候选人、Codex 版本、素材和窗口条件，以便验证证据没有被旧构建冒充。
30. 作为 Codex 用户，我希望失败、取消、窗口隐藏和异常离群样本也被保留，以免报告只展示成功样本。
31. 作为 Codex 用户，我希望日志不包含聊天、凭据、账号或页面可见的完整个人路径。
32. 作为 Codex 用户，我希望实现尽量减少新增文件、进程、服务和状态机，以免后续升级 Codex 时维护成本持续上升。
33. 作为 Codex 用户，我希望新增算法有明确适用条件和安静回退，以免优化路径产生新的播放故障。
34. 作为 Codex 用户，我希望测试集中在真实行为和高风险回归上，以免测试套件因重复和无意义断言变得迟缓。
35. 作为 Codex 用户，我希望项目已有的组件、工具和夹具优先被复用，以免出现两套相似实现和互相漂移的规则。
36. 作为 Codex 用户，我希望图片、Scene、Web 和导入素材的既有行为继续可用，以免视频优化改变其他素材类型。
37. 作为 Codex 用户，我希望性能预算在实施前固定，以免结果不达标后悄悄放宽标准。
38. 作为 Codex 用户，我希望实施后的候选附带用户可执行的检查步骤和已知限制，以便独立复核。

## Implementation Decisions

### 1. 基线、候选与兼容边界

实施必须基于当前支持 Codex `26.1111.2228.0` 的性能设置候选谱系，并包含已经验证的素材传输取消与设置控件回归修复。开始编码前重新核对工作树、未提交改动、实际运行实例和候选指纹，不覆盖现有实现或用户文件。

原有的版本核验、主进程归属、日常 profile、唯一主界面、监听所有者、停用清理和失败保持原界面保护继续有效。速度目标不能成为跳过这些保护的理由。

### 2. File-backed 视频数据通路

创意工坊视频的首选通路为受限本地 File。宿主只接受由已扫描素材 ID 解析出的文件，并对解析结果执行根目录和路径边界校验。页面通过临时隐藏文件输入取得 File 后，使用 CSP 已允许的 `blob:` URL 交给原生视频播放器。

页面不得为该通路接收完整 Base64 视频、完整 MP4 ArrayBuffer 或等大的内存副本。宿主不得向页面暴露绝对路径、无界文件访问能力或用户未选择的任意文件。

现有完整 Blob 传输保留为兼容和回滚通路，只在 File 通路在已核验目标上不可用时启用。每次进入兼容通路的原因必须可观测，不能静默把性能退化当作成功。

### 3. MP4 虚拟布局

对于 `moov` 位于媒体数据之后且布局可证明安全的 MP4，复用上游 MIT 实现的算法思想，只读取文件头部、盒表和 `moov`。宿主修正 `stco` 或 `co64` 中的 chunk offset，页面把修正后的小型索引与 File slices 组合为总长度一致的虚拟媒体。

该能力仅处理兼容的 MP4 `stco` 或 `co64` 布局。分片 MP4、多个媒体数据段、加密或辅助偏移表、偏移越界、索引过大、IO 失败和其他未知布局必须安静回退到原文件。解析过程不得重写源文件，也不得默认启动 ffmpeg、生成等大副本或需要常驻转码服务。

布局解析结果可以在宿主进程内有界缓存，缓存键至少包含文件身份、大小、mtime 和布局版本。没有证据时不得扩大缓存层级或引入通用媒体框架。

### 4. 切换状态机与预热

切换只维护一个当前画面和一个可取消的候选准备。建议的决策型状态如下，来自本轮可行性探针和现有首帧交接逻辑。

```text
idle -> warming -> staging -> committed
          \           \-> fallback
           \-> cancelled
```

- `warming` 仅为一个候选预读元数据，不调用 `play()`。
- `staging` 继续显示旧画面，直到候选拥有正确尺寸并通过首帧就绪判据。
- 新选择递增 generation。旧 generation 的读取、预热、播放器和回调不得提交。
- 停用会让状态进入 `cancelled`，关闭读取、预热计时器、播放器和对象 URL。
- 失败会让状态进入 `fallback` 或保留当前画面的失败态，不得先清空旧画面。

单槽预热只在指针按下、明确悬停且素材为视频时发生。候选变化时释放上一槽。预热不得造成第二个正在播放的视频。

### 5. 启动监督与首屏顺序

启动链合并为一个受保护的 Node 监督进程和同一个 CDP 会话。PowerShell 入口负责必要的入口分发、快速单实例判断和官方激活，然后把控制权交给隐藏监督进程并结束成功路径。监督进程完成目标核验、运行时挂载、宿主连接和当前素材准备。

同一个 Node 进程内复用一次目标发现和一次素材扫描结果。不得同时保留多个相互独立的 CDP 客户端来完成同一启动步骤。启动失败必须关闭对应连接和子任务，不重启或关闭用户已有 Codex。

启动顺序为：

1. 识别手动、登录或已运行复用路径。
2. 执行激活前必须的包、版本和单实例判断。
3. 激活官方 Codex。
4. 在激活后、首次注入前完成其余身份、目标与监听核验。
5. 读取小型当前状态和有效索引。
6. 挂载轻量外观和当前壁纸，准备正式首帧。
7. 首屏后刷新素材库、非当前预览和昂贵维护工作。
8. 用户首次打开设置时再构建完整面板内容。

已运行且专用会话身份匹配时直接聚焦原窗口，不进行素材扫描、CDP 重连或重复注入。

### 6. 持久素材索引

建立版本化的本机素材目录快照，复用现有扫描签名和扫描实现。启动时先检查安装根、Steam 库顺序、扫描根签名和当前素材文件身份。签名匹配时组装已有快照，并在后台定期复核。签名不匹配、缓存损坏、未知版本或当前素材失效时回退完整扫描。

快照使用临时文件加原子替换。写入失败不影响本次运行。新扫描完成前继续保留旧快照。缓存不保存账号、聊天、凭据或无必要页面路径。版本兼容结论、目标核验和监听归属不得缓存。

### 7. 首屏与面板按需构建

启动载荷只包含恢复当前画面所需的轻量信息、必要控制和延迟加载标记。壁纸库完整卡片、非当前预览和完整设置控件不在启动关键路径同步创建。

导入素材拆分为轻量元数据和按需 Blob。当前导入素材需要读取其 Blob，其余导入素材只在用户打开面板、筛选到可见卡片或实际使用时读取。不得为了延迟加载建立第二套持久化状态。

完整面板构建仍使用现有组件和主题。性能改造不得顺带重新设计视觉层级。

### 8. 工程优雅与复用门禁

实现前必须在任务中列出计划复用的现有模块、接口或工具。只有现有能力无法满足已确认需求时，才允许新增抽象。

- 不复制现有扫描、CDP、首帧交接、状态更新、配置保存、控件和测试辅助实现。
- 不为同一含义维护第二套状态变量或平行配置。
- 不引入通用事件总线、插件框架、工作线程池或缓存系统，除非测量证明必要。
- 不保留未被调用的 helper、不可达分支、只服务测试的生产代码或重复清理逻辑。
- 新增算法必须集中在一处，具有明确输入、失败回退、资源上限和独立行为测试。
- 现有的 MP4 兼容判断和 segment 组合应复用同一布局结果，不在多处重复解析。
- 每次审查比较净新增复杂度。若两条路径可以安全合并，优先合并；若兼容路径承担明确回滚职责，则记录保留理由。
- 任何感觉无法解释两个问题内实现意图的代码都不进入候选。

实现完成后必须进行一次独立 Standards 复核，重点回答：是否有冗余代码、是否有过度复杂或私有维护的算法、是否重复实现现有基建、是否有无用测试。

### 9. 测试质量门禁

测试只断言用户可观察行为、公开协议结果、资源生命周期或高风险安全边界。每个新增测试必须能在具体回归出现时失败，不得只检查函数存在、字符串出现、调用次数、实现步骤或同一事实的多个镜像。

新增测试前先检查现有浏览器夹具、宿主测试、PowerShell 启动检查、素材扫描测试和性能探针是否能覆盖同一风险。优先扩展现有最高层夹具，不复制一套近似的测试框架。

删除或合并测试时只处理本功能造成的重复或无意义测试，不顺带清理无关历史测试。

### 10. 视觉责任

执行 agent 负责功能是否可操作、布局是否被遮挡、控件是否可达、性能是否达标，以及录制可检查证据。

执行 agent 不负责判断壁纸是否美观、构图是否满意、透明度是否好看、字体观感、颜色氛围或整体视觉风格是否通过。最终视觉验收由用户完成。缺少用户确认时，候选状态为“功能与性能完成，待用户视觉验收”。

### 11. 诊断与隐私

启动回执使用统一的单调时间点并绑定候选身份。至少记录入口开始、包核验、激活、主进程、目标核验、会话连接、缓存命中、运行时挂载、宿主就绪、当前素材源就绪、壁纸首帧、素材库就绪和复用结果。

记录扫描条目数、读取字节、CDP 连接数、主进程数、播放器数和缓存命中状态。日志不记录聊天正文、凭据、账号标识或页面可见的完整个人路径。诊断采集只在需要时启用。

## Testing Decisions

### 1. 测试 seam

只采用两个层级，优先级从高到低。

1. **真实 Codex 端到端 seam。** 从专用入口启动实际包，在唯一主页面使用真实素材、真实点击和真实前台可见状态完成切换、启动、停用和复用验收。这是最终通过依据。
2. **现有浏览器与宿主行为 seam。** 复用当前运行时夹具和宿主协议测试，验证首帧交接、快速取消、文件缺失、旧请求隔离、状态清理、缓存失效和路径边界。自动化结果只作为回归证据，不替代真实 Codex 性能与用户视觉验收。

不为本功能另建第三套测试服务器、通用浏览器框架或独立状态模拟器。启动链的真实时序由同一个专用入口探针记录，不在离线夹具中伪造系统启动时间。

### 2. 切换验收

固定以下素材：

- 约 110 MiB、`moov` 前置的 H.264 视频。
- 约 75 MiB、`moov` 后置的 H.264 视频。
- 当前已知的大型视频压力素材。

冷切表示当前进程中尚未建立该素材的 File、播放器或元数据。热切表示候选已经预热或本进程内成功播放。真实动态帧必须同时满足前台可见、视频未暂停、`readyState` 足够、连续两帧 `requestVideoFrameCallback` 的 `mediaTime` 前进，并且录屏中至少出现两帧可辨认运动画面。

| 指标                     |           采样 | 门槛                                       |
| ------------------------ | -------------: | ------------------------------------------ |
| 点击到选中反馈           |          30 次 | p95 ≤ 50 ms，最大 ≤ 100 ms                 |
| 点击到精确过渡画面       |          30 次 | p95 ≤ 150 ms，最大 ≤ 250 ms                |
| 冷切到真实动态帧         | 每种布局 20 次 | p95 ≤ 600 ms，最大 ≤ 1000 ms               |
| 热切到真实动态帧         | 每种布局 20 次 | p95 ≤ 300 ms，最大 ≤ 500 ms                |
| 快速选择最终落到最后一项 |          20 组 | p95 ≤ 800 ms，最大 ≤ 1200 ms               |
| 切换中停用               |          10 次 | 500 ms 内清理，之后 30 秒不复活            |
| 可控失败                 |          10 次 | 旧画面保留，错误明确，无黑屏或默认背景闪入 |

首帧出现时不得接收完整 video Base64。对首帧前读取字节、页面堆增量、宿主峰值和播放器数量进行记录。File 通路通过不等同于磁盘零读取，报告必须区分页面副本、浏览器读取和系统缓存。

### 3. 启动验收

启动测量区分：

- 官方 Codex 原入口。
- 专用入口。
- DSH 原项目同机体验基准。
- 冷开无缓存。
- 有效缓存热启动。
- 已运行专用实例复用。
- 登录自启动的既有配置路径。

统一时间点：

- `T0` 用户双击或系统登录触发。
- `T1` Codex 主进程创建。
- `T2` 主窗口首次可见。
- `T3` 唯一 `app://-/index.html` 目标核验完成。
- `T4` 运行时和宿主就绪。
- `T5` 壁纸首次可见。
- `T6` 视频首次真实动态呈现。

冷启动样本量不足以严谨计算 p95 时，报告至少 5 次原始值、中位数和最大值。热启动和复用默认采样 20 次。任何异常样本保留并注明原因，不通过删除离群值制造通过。

### 4. 行为回归

- File 通路成功时只有一个活动媒体，正式首帧前旧画面不消失。
- 前置和尾部 `moov` 视频分别组帧成功，虚拟媒体总长度与源一致。
- 不支持或损坏的 MP4 安静走兼容路径或显示旧画面。
- 快速 A→B→C 和 A→B→A 只提交最后选择。
- 切换中停用后无文件句柄、对象 URL、预热计时器、播放器或待处理回调残留。
- 文件被删除、读取拒绝、虚拟布局失败和视频解码失败均保留旧画面。
- 单槽预热最多一个元素，不调用播放，候选变化后旧槽释放。
- 有效缓存命中时不枚举全部项目，后台复核失败不影响当前索引。
- 损坏、旧版本和签名不匹配缓存回退完整扫描，不阻塞聊天输入。
- 已运行复用路径没有新主进程、重复注入或扫描。
- 版本或主界面不匹配时保持原生界面，不创建宿主和壁纸节点。
- 导入 Blob 延后读取后，图片、视频、删除和重新打开面板行为保持。
- 图片、Scene、Web 和现有设置/快捷键路径通过相关回归。
