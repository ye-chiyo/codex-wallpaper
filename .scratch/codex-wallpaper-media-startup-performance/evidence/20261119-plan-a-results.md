## 根因与修复

12 次同素材试验中有 3 次首帧未提交，完全透明和 1% 透明暂存层均能复现。三次都注册并收到一次 rVFC，交付时已有 1920×1080 尺寸但 `readyState=1`，1.0–1.4 ms 后发出 `loadeddata` 和 `playing`，状态升到 4。原代码在第一个回调时提前返回，未继续等待。现有浏览器夹具先让同一故障失败，再验证回调重挂、保留原画面、下一次有效帧提交。保留暂存层透明度和原有画质设置。[根因原始时序](20261119-plan-a-handoff-162232.json)

移除悬停和仅按下的 File 请求、临时播放器和宿主预热协议。选中状态只更新相关卡片，视频确认后才启动既有 File 路径。切换和停用关闭待处理 File 输入和播放器，退休播放器主动释放源。现有 MP4 分段、扫描与路径保护、原生播放器、已记录原因的兼容回退继续使用。宿主区分已取消与 File 通路不可用。真实宿主进程的协议夹具验证旧 File 请求被取消后重试最新请求，取消未触发完整文件回退。独立审查发现这一问题和宿主成功 File 路径覆盖不足，现有宿主回归已补齐。没有新增媒体算法、第二套扫描或测试框架。启动监督工作来自方案 A 之前的工作树。

`pnpm test` 全部 36 项通过。增强原有首帧交接、视频卡片、File 取消和单会话宿主回归，仍使用现有浏览器及宿主夹具。复核清理路径后，产品代码无旧的预热调用或新增测试专用分支。
