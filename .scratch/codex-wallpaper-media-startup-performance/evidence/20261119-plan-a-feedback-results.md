# 方案 A 选中反馈呈现复测

## 根因

实机记录了受信任点击、卡片选中属性更新、绘制前回调和 Chromium 呈现。初次诊断中，浏览器记录的点击到呈现为 72–112 ms。暂停滚动后再点击，或直接触发同一按钮的 DOM 点击，仍能观察到相近的渲染等待。仅更新卡片标记、拦截壁纸请求的对照也复现了长样式重算。轻量跟踪中，主线程 `UpdateLayoutTree` 的一段耗时约 84–115 ms。

逐组停用样式后定位到设置页的根选择器 `[data-app-shell-feature-navigation='true']:has([data-settings-nav-scroll-container])`。原先把全部设置页后代规则嵌套在这个关系选择器下。只停用该规则时，普通聊天同一卡片的强制样式与布局阶段由约 70–81 ms 降到 12–13 ms。改用单条设置页匹配规则与 CSS 样式查询后，另外一轮同一探针对照由约 69–72 ms 降到 14–15 ms。重写保留原有设置页材料和声明，沿用已有递归样式绑定，对现有应用无额外监听器、计时器或常驻状态。

详细选择器统计开启后增加了明显负荷，已终止那次探针并从原备份恢复。窗口进程未结束。该试验未纳入任何计时结果。

## 呈现复测

同一台机器和真实专用实例临时切换改前、改后样式。前置和尾置视频每轮各 20 次，均从受信任点击计时。卡片属性与「当前」标记在绘制前回调确认。按每次点击匹配 Chromium `EventTiming` 开始和结束记录，并校验结束点晚于该次反馈回调。每轮 40 条完整配对。早期调试中一列派生结束时间配对有误，对应文件保留作诊断，下面只用修正后的数据。

| 轮次 | 改前 p95 | 改后 p95 | 改后最大 | 改后 50 ms 内样本 |
| --- | ---: | ---: | ---: | ---: |
| 第一组 | 94.5 ms | 31.9 ms | 53.2 ms | 38/40 |
| 第二组 | 120.8 ms | 74.9 ms | 81.0 ms | 29/40 |

改后第一组前置和尾置 p95 分别为 31.3 ms 和 31.9 ms。第二组分别为 74.9 ms 和 55.3 ms。两组均有明显改善，一组达到 p95 ≤ 50 ms，当前证据未核准稳定达标。追加的复杂页面诊断在可见页面记录约 8,046 个元素，部分慢点击伴随 1,900 余元素样式重算，后续较快点击约 690 个。仍会受应用页面工作影响。额外诊断开启更多跟踪类别，样本不计入呈现验收。

## 输入和滚动

同一前台聊天视图、尾置视频稳定播放，并保持相同壁纸设置。实测向空编辑器输入单字符后删除，以及会话区域滚轮滚动。两项各 16 次，由事件计至更新后的第二次渲染回调。此次对照里输入 p95 从 179.9 ms 降到 80.2 ms，滚动由 26.5 ms 变为 25.2 ms。两轮试验恢复输入内容和滚动位置。此前有一轮滚动探针命中问题，超时样本保留，结果未计入此次成对统计。样本支持本轮未见输入和滚动回退。

## 200 ms 可行性

两轮修改后各 40 次，正确画面最快约 97 ms，65/80 在 200 ms 内完成 DOM 交接，两轮交接 p95 分别为 287.1 ms 和 302.7 ms。连续动态帧分别为 p95 382.0 ms 和 408.4 ms，80 次中最快约 202.4 ms。某些样本在 File 交付完成时已用 200 ms 以上，后续仍要完成解码和浏览器呈现。当前条件下，无法保证每次以原画质完成 200 ms 切换。保持点击后按需读取、悬停不准备视频，方案 B 和专门追 200 ms 的修改暂不实施。
