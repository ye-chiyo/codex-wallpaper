# Codex 主界面壁纸运行时清理与回归验收

Status: ready-for-agent

日期 2026-11-20。范围以用户已审核通过的只读审计为准，在 `codex/wallpaper-performance-settings` 的当前工作树上分批推进。

## Problem Statement

专用入口在冷启动页面切换时可能于核验 Codex 主界面后断开 CDP 会话。两次真实启动都停在 `verified`，随后报注入失败。页面稳定后手工接回监督进程可以恢复当前壁纸，下次从专用入口启动仍会遇到同一握手风险。

素材切换、停用和设置目前共用一套运行时。审计确认其中有可以移除的旧状态和重复工作，也有需要先修的资源生命周期问题，包括 Scene Blob URL 未回收、完整重置后重新启用失去工坊素材宿主，以及畸形 MP4 布局可能卡住读取。已有自动化通过，实机也有代表性成功样本。当前候选仍缺少从专用入口到同版本首帧、快速选择、失败回退和交互响应的完整证据。用户已完成一次视觉验收。

## Solution

先让专用入口在页面切换后重新核验并恢复壁纸，再逐批修复媒体和资源问题，最后删除或合并有证据支持的冗余。用户继续使用原有素材、画质、布局和设置。视频从确认点击开始按需准备，旧画面持续显示到有效首帧可以交接，快速选择只提交当前有效选择。

最终使用同一候选的专用入口和真实主界面验收。保留现有浏览器与宿主夹具，分别验证页面行为及启动和媒体协议。每个批次可独立验证，并能从原始证据区分启动成功、手工恢复宿主和临时页面探针。

## User Stories

1. 作为 Codex 用户，我希望专用入口在冷启动后自动恢复上次壁纸和布局，以便直接进入日常聊天。
2. 作为 Codex 用户，我希望启动时主页面更换后可以继续完成挂载，以便冷启动的短暂页面切换无需手工介入。
3. 作为 Codex 用户，我希望只在匹配的 Codex 包、日常 profile 和主界面上启用壁纸，以便其他实例、头像层和分离窗口保持原态。
4. 作为 Codex 用户，我希望重复打开入口只复用已验证的专用实例，以便壁纸、控件和宿主各自维持一份。
5. 作为 Codex 用户，我希望继续打开现有账号和聊天，以便专用入口适用于日常使用。
6. 作为 Codex 用户，我希望启动时优先恢复当前画面，打开壁纸库时再构建完整卡片，以便尽快使用聊天。
7. 作为 Codex 用户，我希望关闭并重开壁纸库时保留现有卡片，以便避免重复构建并保持搜索与筛选可用。
8. 作为 Codex 用户，我希望浏览和悬停卡片时只使用可见预览，以便免于同时读取和解码多个主素材。
9. 作为 Codex 用户，我希望按下后取消点击时维持现状，以便误触不切换壁纸。
10. 作为 Codex 用户，我希望点击后立即看到选中和加载反馈，以便知道本次选择已经收到。
11. 作为 Codex 用户，我希望正常切换图片、前置及尾置 `moov` 视频，以便继续使用现有素材库。
12. 作为 Codex 用户，我希望吊桥等超过 512 MiB 且处于 File 上限内的视频能按需播放，以便大视频也有原画质通路。
13. 作为 Codex 用户，我希望 4K90 切换到《鸣潮》今昔时新视频进入实际当前层，以便看到新画面和连续运动。
14. 作为 Codex 用户，我希望原始素材、视频尺寸、布局、声音及隐藏暂停设置继续生效，以便已有偏好保持一致。
15. 作为 Codex 用户，我希望 A→B→C 和 A→B→A 都由最后一次选择决定，以便迟到的交付或错误不会覆盖最新结果。
16. 作为 Codex 用户，我希望视频首帧过早回调或页面暂时不可见时仍可正确交接，以便恢复前台后看到正确素材。
17. 作为 Codex 用户，我希望素材缺失、读取或解码失败时保留旧画面并指出失败，以便选择重试或换用其他素材。
18. 作为 Codex 用户，我希望在无旧画面时仍有作者预览或内置背景，以便初次加载失败时界面依然可用。
19. 作为 Codex 用户，我希望停用立即取消正在读取或等待首帧的素材，以便背景消失后不会复活。
20. 作为 Codex 用户，我希望切走、停用或重置 Scene 和视频后释放其资源，以便长时间使用时避免资源累积。
21. 作为 Codex 用户，我希望软件核验当前允许根和文件状态，以便目录变化或文件删除后不会交付旧索引中的失效素材。
22. 作为 Codex 用户，我希望修改设置后关闭重开仍保留最终值，以便滑杆预览和跨窗口同步不会丢失有效修改。
23. 作为 Codex 用户，我希望导入、导出、预设和重置仍遵循现有设置格式及范围，以便继续使用已保存配置。
24. 作为 Codex 用户，我希望完整重置后仍能重新启用并选择工坊壁纸，以便双确认清除完成后可以从默认状态重新使用。
25. 作为 Codex 用户，我希望切换和播放期间聊天输入与滚动保持响应，以便壁纸可以持续运行。
26. 作为维护者，我希望每项删减能说明旧代码对应的场景和接手路径，以便识别仍在使用的兼容回退。
27. 作为维护者，我希望看到启动、宿主、首帧及性能各阶段的原始证据，以便准确评估每批变化和最终候选。

## Implementation Decisions

### 工作树与实施顺序

- 以当前脏工作树为基线，保全既有修改、规格、证据和未跟踪探针。沿用当前分支，禁止 reset、checkout、clean、覆盖或删除用户文件。
- 按下面的顺序实施。每次只做一个可验证的批次，记录变化、测试结果和实机验收状态，再进入下一批。
  1. 启动握手与真实目标变更。
  2. MP4 边界、迟到的 File 错误、Scene 资源释放、完整重置恢复，各自独立验证。
  3. 纯删减。
  4. 资源清理与交付完成合并、卡片和设置原位更新、扫描快照与路径边界，按职责分批。
- 将启动仍读取完整导入记录和构建设置控件的事实保留在验收记录。完整导入存储改造及更大范围的启动优化沿用原性能规格单独跟踪。

### 专用入口与监督进程

- 保留现有包版本和可执行文件核验、日常 profile、主进程与环回监听归属、唯一精确主页面与 frame 来源核验。目标不匹配时保持原界面。
- 沿用现有 `openMainPageSession`、`attachWallpaperHost`、`sessionEvaluate` 和父子进程握手。启动期目标短暂消失时，在现有 25 秒启动时限内重新发现并核验，重新执行入口侧本机复核。父进程取消与 CDP 目标丢失使用各自的生命周期结果。失去旧会话时回收其连接、锁和本次部分挂载。
- 回执分别记录目标核验、宿主就绪或失败阶段。已成功保留的宿主与页面身份可以对应到同一主实例。目标和宿主就绪后才写入可复用会话标记。首帧、动态呈现和聊天可操作另外取证。
- 继续复用 `runtimeSource` 和 `candidateIdentity`。验收记录运行中的包、主进程、端口、目标、宿主、页面运行时与实际样式指纹。记录尚无独立宿主模块指纹时的证据边界。

### 媒体、配置与清理

- 沿用供应商扫描、预览、`prepareWallpaperAsset` 和 `prepareMp4VirtualLayout`。项目记录与允许根来自同一份扫描结果，实际交付仍按真实路径、文件存在性及大小复核。缓存过期继续用已有签名和后台复核；文件删除、根目录变化、复核失败要有可观察的结果。已挂载页面的目录同步如需调整，复用现有刷新机制并保留待保存设置。
- 视频 File 上限维持 1 GiB，完整 Base64 兼容回退维持 512 MiB，预览维持单项 2 MiB。首选现有 File 交付和对象释放。小素材 File 对象缺失或 File 通路确实不可用仍可回退；被取消的请求与超出 Base64 上限的视频均不得启动完整 Base64。
- 复用现有 MP4 分段逻辑。验证盒尺寸与前进条件、`stco/co64` 表的结构、有效媒体数据偏移及资源预算。扩展长度异常、布局超出支持范围或无法证明可安全调整时，继续使用原 File。保留 4 MiB `moov`、2 MiB 偏移表总预算和单表 100,000 项限制。
- File 成功、取消及错误都服从当前请求和选择代次。同 ID 快速重选必须隔离先前请求的迟到结果。仅在确认无 `change` 事件或同类真实挂起路径后，才为现有交付增加必要上限。
- 继续用 `runtimeAssets` 记录实际交付。首帧前保留旧画面，早到且数据不足的回调继续等待有效帧。保留可见性恢复和兼容回退。视频、Scene、候选 Blob、临时输入和对象引用在各自的取消、失败、退休或停用路径释放。
- 复用现有停用与重置的公共清理。完整重置保留双确认、跨窗口协调、导入数据清除及默认状态。重新启用后使用工坊素材需要有可用宿主，入口复用结果不得把失去宿主的实例当作已就绪。按正常停用后再次启用仍恢复既有选择和设置。
- 继续使用现有配置持久化、跨窗口字段合并、设置控件、导入导出和预设迁移。关闭重开保留最终值；有待保存字段时，停用用一次最终写入保存设置和启用状态。卡片变化用原位更新，按需预览保持筛选、打开、切页和滚动可用。

### 纯删减与合并边界

- 首批纯删减限于无读取的旧帧统计字段、无读取的播放对象标记、无人设置的旧播放回调字段、已有入口条件排除的分支，以及虚拟布局中一次重复的索引复制。保留探针使用的状态字段。实现函数的导出仅在确认现有调用方均经公共入口后收回。
- 合并范围限于两个以上已有调用点的相同职责。优先处理停用和重置的公共清理，File 与 Base64 的成功登记，卡片单项查找，以及现有设置控件的原位同步。各交付通路继续管理自己的取消、类型、长度和兼容边界。
- 可见预览有两条触发路径。拟合并时，先用现有夹具确认首次打开、滚动、新筛选结果和切页的预览行为均能继续触发。原 File、受限 Base64、作者预览、Web 离线沙箱、Scene 渲染器回退及现有独立诊断入口有明确使用场景，均保留。

## Testing Decisions

### 接入点与回归

- 最高接入点为真实专用入口加载同一个候选后，在主界面进行用户操作。确定性回归复用现有浏览器和真实 PowerShell/Node 宿主协议夹具，素材扫描与 MP4 沿用现有测试。保持现有测试服务器与浏览器框架数量。
- 只断言用户可见结果、协议结果、状态持久化或资源生命周期。保留对不同边界有保护的测试。大文件成功与失败用例可合并共同夹具准备，分别保留结果。来源测试只保留各接入点的独有结果。原先只匹配绑定或表达式字符串的持久化停用用例应验证实际停用状态、热键恢复和随后 File 交付。
- 新增一个最高层确定性启动回归。已验证页面在 `verified` 后断线，新精确目标出现。验证重新核验、单宿主、旧锁释放和新实例成功交付首个素材。复核拒绝时检查原界面及错误回执。
- 扩展已有 File 回归，让宿主生成的 objectId 表达式能被实际解析，浏览器夹具能观察到 File 对应 Blob 成为当前画面。保留 objectId 缺失时小文件有界回退、大文件无完整 Base64 的独立结果。
- 扩展已有缓存回归，覆盖复核跨越删除或根变更时的交付拒绝和新快照一致性。扩展既有 MP4 用例，覆盖畸形扩展长度及时拒绝与原 File 路径，并补足改动涉及的 `co64` 或偏移边界。
- 扩展已有首帧回归，同时观察早到回调时旧节点仍在、有效回调后新画面提交、取消后没有暂存或迟到复活。Scene 释放、旧 A 失败晚于新 A 请求、停用和完整重置后重启用优先增强现有生命周期用例。
- 启动批运行只读探针、宿主及启动交接用例和三个 PowerShell 预检。媒体各批运行相应 MP4、File、首帧、取消、失败、Scene 或重置测试。缓存与设置批运行素材库或对应浏览器回归。每批报告定向测试和完整 Node 套件结果，涉及候选标识运行身份探针测试。

### 最终验收

| 门禁 | 必须记录的结果 |
| --- | --- |
| 专用入口 | 从真实入口启动，阶段回执完整，主界面身份正确，只有一个宿主，恢复当前素材；记录首次正确画面和视频推进帧。 |
| 按需壁纸库 | 首次打开前完整卡片为 0，打开后可用，关闭重开复用；悬停和仅按下没有主视频 File 交付或解码。 |
| 代表素材 | 普通图片、115,500,404 B 前置 `moov`、75,689,196 B 尾置 `moov`、564,467,901 B 吊桥、4K 视频。额外确认 4K90 →《鸣潮》今昔进入当前层，连续两个呈现回调的 `mediaTime` 前进，交接后零暂存层及零临时输入。 |
| 选择、停用与故障 | A→B→C 和 A→B→A 只提交最后一次有效选择；停用后记录播放器、输入和暂存层计数及 30 秒观察；文件缺失、读失败、解码失败保留旧画面并报告明确状态。使用专为验收准备的素材，保全用户文件。 |
| 设置 | 打开、修改、关闭、重开及跨窗口同步，检查最终值和保存次数；导入导出或分组重置维持原范围，使用隔离的验收配置和导入素材验证完整重置、重新启用及工坊 File。 |
| 日常交互与性能 | 同一机、同素材、同可见性和设置下保留点击反馈、首次正确画面、动态帧、聊天输入、滚动及资源采样。记录时间起点、系统缓存状态、超时与失败。 |

- 沿用媒体启动规格及方案 A 已定的采样量和预算。主要门槛包括反馈 p95 ≤ 50 ms、精确过渡 p95 ≤ 150 ms、冷切动态帧 p95 ≤ 600 ms、同进程已播放后的重复切换 p95 ≤ 300 ms、快速选择 p95 ≤ 800 ms，以及停用 500 ms 内清理和随后 30 秒无复活。热切须采用已成功播放的同进程样本，悬停和按下均维持按需约束。原规格最大值、启动分阶段指标及采样规则继续适用。
- 每项附实际命令或操作、原始证据路径、候选身份和结论。分开标注自动化、真实专用入口、真实页面临时注入或手工接回、未验证。启动回执与试播结果分别记录。历史通过样本保留其候选身份和计时口径。
- 用户已完成的视觉验收保留为既有结论。后续变更若需要补视觉结论，由用户判断。真实冷启动待用户明确授权关闭或重启当前 Codex 后执行。

## Out of Scope

- 重做整个壁纸运行时、从 `master` 重新实现、原入口自动接入、自动注册登录入口或改变 Codex 包、日常 profile、账号及聊天数据。
- 修改素材文件、转码、降画质、引入悬停或按下预热、实施方案 B、引入新的常驻媒体缓存。
- 增加测试服务器、浏览器框架、通用缓存层、事件总线、线程池、转储服务或第三套近似测试框架。
- 提交、推送、远程 PR，以及未经明确要求关闭或重启当前 Codex。
