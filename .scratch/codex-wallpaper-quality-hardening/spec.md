# Codex 壁纸候选版缺陷修复、端到端验收与代码质量收敛

**Status:** ready-for-agent

## Problem Statement

Codex 壁纸的统一候选版已经能在专用入口中显示，但还不能把“源码已实现”“自动测试通过”“真实 Codex 已跑通”和“长期稳定”混为一谈。当前用户能看到的主要问题与风险是：

- 点击 Codex 的“变更”后，主聊天页面变为不可见，Codex 打开独立的 `detached-window` 页面；壁纸只存在于主聊天页面，因此用户会看到背景消失或闪黑。现有证据表明根层、样式和 Scene 没有重复实例，问题来自页面承载范围不足。
- 输入框后方曾出现比输入框大得多的黑色底衬。根因是 `[data-thread-scroll-footer]` 内的通用表面被壁纸样式整体加深；当前已有未提交修复和计算样式证据，但尚未完成统一回归、提交和真实视觉验收。
- 多次切换壁纸时曾出现旧 Scene 与新 Scene 交替、旧异步回调重启当前壁纸、预览和播放器短暂重复。相关代次隔离已实现，但缺少覆盖“主聊天与变更页切换”的完整业务回归。
- 壁纸库曾把已下载素材大量标为“不可播放”或“预览降级”。根因是旧预览和主素材预算过小；现已改为可见卡片按需加载、选中后按需读取，但仍需用真实样本确认加载状态、预览降级和最终播放结果没有再次混淆。
- 专用启动器曾把主页面和 Avatar 辅助页面误判为歧义目标；也出现过背景层被宿主内容遮挡、快捷键只能开启不能关闭。这些问题已有修复，但必须继续作为回归项，避免后续跨页面改造重新引入。
- 当前自动测试主要验证无头页面、CDP 边界和宿主失败路径，尚未完整模拟“从专用入口打开、进入已有聊天、选择素材、调整设置、切换变更页、返回、停用、重开恢复”的真实业务链路。自动测试通过不能替代真实 Codex 的端到端与视觉验收。
- 运行时集中包含配置、界面、素材加载、播放器生命周期、IndexedDB 和宿主协议。部分共享能力已经存在，但若继续为不同页面复制播放器、请求通道或状态机，会快速增加维护成本。
- 原入口自动接入、联网 Web 隔离、创意工坊全量兼容、8 小时基础验收和 7 天长期观察仍未完成，不能在本次缺陷修复中静默记为通过。

## Solution

在不关闭、重启或连接用户正在使用实例的前提下，把当前候选版收敛为一个可重复验证的质量基线：

1. 让主聊天与 Codex“变更”页面使用同一套壁纸运行时契约，在用户切换页面时保持相同壁纸可见；加载中的素材显示当前作者预览或已有画面，不允许退回默认渐变、黑底或出现重复播放器。
2. 保留输入框本体的可读实底，只移除输入框后方的宿主大底衬；不得通过删除宿主界面或修改受保护安装文件解决视觉问题。
3. 将已经修复的黑底衬、快捷键、目标歧义、层级遮挡、旧异步回调和素材按需加载逐项绑定到可复现的用户行为回归。
4. 以真实 Codex 的完整使用链路做端到端和视觉验收，并分别记录源码、自动测试、候选部署、真实运行和人工接受结果。
5. 只在主聊天、变更页和宿主确实共享的能力处复用现有运行时、页面注入、素材请求和配置接口；不为修复增加第二套播放器、平行状态机、无边界重试或通用插件框架。
6. 对现有测试做一次以用户行为为准的审计：保留能防止真实回归的测试，删除只断言私有实现、重复覆盖同一行为或需要维护脆弱内部细节的测试。

## User Stories

1. 作为 Codex 用户，我希望从专用入口进入已有聊天后直接看到上次选择的壁纸，以便不重复设置。
2. 作为 Codex 用户，我希望点击“变更”时壁纸继续覆盖当前可见页面，以便页面切换不产生黑闪。
3. 作为 Codex 用户，我希望从“变更”返回聊天时仍看到同一壁纸，以便来回检查代码和聊天时视觉连续。
4. 作为 Codex 用户，我希望变更页加载素材期间显示作者预览或已有画面，以便不出现默认渐变或空白过渡。
5. 作为 Codex 用户，我希望主聊天和变更页不会同时播放两份动态素材，以便控制内存和显卡开销。
6. 作为 Codex 用户，我希望输入框后方不再出现大块黑色矩形，以便壁纸连续显示且输入区仍然清晰。
7. 作为 Codex 用户，我希望输入框本体保持足够实底，以便长文本、选区和快捷键始终可读可用。
8. 作为 Codex 用户，我希望工具卡片、代码、差异和面板保留局部读底，以便壁纸不会降低工作内容可读性。
9. 作为 Codex 用户，我希望壁纸层不拦截点击、滚动、文本选择、复制和键盘输入，以便宿主操作不受影响。
10. 作为 Codex 用户，我希望连续切换图片、视频、Scene 和 Web 预览时旧素材彻底停止，以便背景不来回闪动。
11. 作为 Codex 用户，我希望旧素材迟到的回调不能重启当前壁纸，以便快速切换后只保留最后一次选择。
12. 作为 Codex 用户，我希望已下载素材在真正读取前显示“按需加载”，而不是被误标为损坏，以便准确理解壁纸状态。
13. 作为 Codex 用户，我希望选中未预载素材时先显示作者预览，并在主素材就绪后无跳闪地替换，以便加载过程自然。
14. 作为 Codex 用户，我希望 Scene 首帧就绪后才移除预览，以便 WebGL 初始化和切换过程不出现空白。
15. 作为 Codex 用户，我希望 `Alt+Shift+W` 在开启和关闭之间可靠切换，以便不打开设置面板也能即时停用。
16. 作为 Codex 用户，我希望停用后适配新增的背景、控制按钮、样式和播放资源立即消失，以便恢复原 Codex 界面。
17. 作为 Codex 用户，我希望停用状态在重开后保持，并能通过按钮或快捷键重新开启，以便启停行为可预测。
18. 作为 Codex 用户，我希望专用启动器只选择无查询参数的真实主页面，并忽略 Avatar 等辅助页面，以便冷启动不因目标歧义失败。
19. 作为 Codex 用户，我希望重复点击启动器只复用当前候选实例，以便不产生多份监听或播放器。
20. 作为 Codex 用户，我希望主聊天与变更页使用同一全局选择和视觉设置，以便切换页面后不需要重新配置。
21. 作为 Codex 用户，我希望两个页面中的壁纸状态可以共享，但不复制大体积素材处理逻辑，以便运行更稳定、维护更简单。
22. 作为 Codex 用户，我希望最小化或不可见页面暂停播放，恢复可见后自动继续，以便节省资源。
23. 作为 Codex 用户，我希望素材读取失败时保留预览或静态降级，并让 Codex 继续工作，以便故障不阻塞聊天。
24. 作为 Codex 用户，我希望测试直接覆盖用户能观察到的页面、画面、交互和恢复结果，以便测试通过能说明业务真的跑通。
25. 作为 Codex 用户，我希望不再维护只验证内部变量、重复检查同一 CSS 字符串或模拟私有实现的测试，以便测试套件更快且更可信。
26. 作为 Codex 用户，我希望代码继续复用已有配置读取、素材类型判断、素材请求、页面注入和运行时 API，以便避免同一能力出现多个版本。
27. 作为 Codex 用户，我希望跨页面修复不引入新的长期运行状态机、无限重试或脆弱轮询，以便后续 Codex 更新时仍能定位和修复。
28. 作为 Codex 用户，我希望交付前看到真实 Codex 的视觉检查证据，以便黑闪、黑矩形、层级遮挡和不可读问题不会再次留给我发现。
29. 作为 Codex 用户，我希望完整业务链路经过自动回归和真实端到端验收，以便明确知道功能处于“已实现”“已测试”还是“已实际跑通”。
30. 作为 Codex 用户，我希望未完成的联网 Web、原入口自动接入和长期稳定结论继续明确列为边界，以便候选版不被误认为已经全面完成。

## Implementation Decisions

### 页面与运行时边界

- 扩展现有页面注入能力以承载两个已核验的 Codex 页面：无查询参数的聊天主页面，以及 Codex“变更”使用的 detached 页面。目标选择继续复用只读目标发现、精确 URL 和环回监听归属核验。
- 两个页面使用同一个运行时契约、同一份全局配置和同一种素材状态表达。现有 `__codexWallpaperApi` 作为唯一运行时入口，继续提供启用、停用、刷新、状态和素材接收行为。
- detached 页面的具体可见表面和样式锚点必须先通过真实 DOM 证据确认，再增加必要选择器。不能凭页面 URL 直接假设其 DOM 与聊天主页面相同。
- 页面切换时，当前壁纸选择保持不变。无法立即取得完整主素材时使用该素材已有的作者预览或上一帧，不使用内置渐变作为正常切换过渡。
- 同一时刻只允许当前可见页面播放动态素材；不可见页面必须暂停或释放活动播放资源。两个页面可以各自保有已注入的空壳，但不能各自维护独立素材库或独立配置真源。
- 素材按需读取继续复用现有本机宿主和 binding 协议。若宿主需要服务两个页面，应以同一请求处理和同一素材准备函数服务多个已核验页面会话，不复制扫描、分块传输、Scene 引擎加载或 Web 沙箱逻辑。
- 页面不可见、页面销毁、停用和运行时替换继续复用现有可见性监听、代次隔离和清理路径。修复跨页面问题时不新增第二套启停状态机。

### 视觉与交互

- 输入框后方的 `[data-thread-scroll-footer]` 大底衬保持透明；输入框本体、工具卡片、代码块、差异视图、侧栏、面板、弹窗和设置仍使用足以阅读的局部实底。
- 壁纸根层继续保持不接收指针。控制按钮和设置面板位于独立高层，不能遮挡输入、卡片操作或页面滚动。
- 明暗主题下读取 Codex 已有颜色变量，不维护另一套固定主题色表。只有 Codex 未提供稳定变量时才使用单一本地回退值。
- 变更页的适配范围聚焦背景连续与宿主可读。除非真实 DOM 证明需要，不为 detached 页面重做一套完整聊天表面规则。
- 所有新增 CSS 选择器必须对应已复现的 Codex 结构或稳定语义属性；不得为了“可能有用”扩大全局选择器。

### 质量与复用

- 优先复用已有 `readConfig`、`libraryEntries`、`findEntry`、`mediaType`、`requestResult`、素材请求集合、可见性同步和页面注入函数。只有出现第二个真实调用方时才提取共享函数。
- 不整体拆分类似单体运行时的文件。跨页面改造只需要抽出两个页面和宿主都实际共享的最小接口；避免为了形式上的模块化增加转发层。
- 不为单个失败增加无限重试、指数退避、后台守护或复杂调度。当前按需请求、活动代次和单次降级已经覆盖已知问题；新材料证明需要前不扩展。
- 每次修复先写一个能复现用户问题的行为回归，再修改实现。测试名称应描述用户可见结果，例如“变更页保持当前壁纸”，而不是私有函数名。
- 测试审计逐项记录“对应哪个已复现问题”。没有对应问题、只断言实现细节或与另一测试完全重复的用例应删除或合并。
- 不要求每个工具函数都有测试。优先在最高现有接缝验证完整行为；只有纯函数承载独立且高风险协议时保留单元测试。

### 业务闭环

- 当前候选版的完整业务终点是用户在真实 Codex 中看到并操作最终壁纸画面；本项目没有导出步骤，因此端到端验收覆盖“启动/进入聊天 → 选择素材 → 调整设置 → 切换变更页并返回 → 停用与恢复 → 重开恢复”的完整可见结果。
- 自动测试需要覆盖同一链路中可稳定复现的页面、状态和资源数量；真实 Codex 端到端验收覆盖实际主题、真实 DOM、视觉连续性、点击和键盘操作。
- 修复只对受影响的已验收场景要求重新确认。跨页面承载、播放器生命周期或宿主协议发生变化时，必须重跑页面切换、素材切换、停用恢复和单实例检查。

## Testing Decisions

### 测试原则

- 只从用户可观察行为、公开运行时 API、页面计算样式、真实点击/键盘事件和资源数量验证结果，不断言内部变量、函数调用次数或完整 CSS 文本。
- 复用 `applyStaticBackground`、`evaluateInPage`、`runtimeSource`、`__codexWallpaperApi`、现有 headless Edge fixture 和本机宿主协议作为最高测试接缝。
- 一个测试可以包含同一业务流程的多个断言；只有需要不同浏览器状态或失败恢复时才增加新进程。避免每个小断言启动一次浏览器。
- 测试证据区分自动回归和真实宿主人工结果。两者都通过后，才把对应业务项记为跑通。

### 自动回归

1. **页面承载回归：** 使用现有 headless Edge 建立聊天主页面和 detached 变更页面，注入同一运行时，激活不同页面并切换回来。验证当前可见页面有且只有一层壁纸、停用按钮可命中、不可见页面暂停，来回切换不出现黑底或默认渐变。
2. **素材连续性回归：** 用当前已有图片、视频、Scene 和 Web 预览夹具快速切换。验证旧回调不能重启当前选择、最终只有一个活动播放器，未加载主素材时保留预览，Scene 首帧前保留作者预览。
3. **输入区与层级回归：** 继续使用现有计算样式和 hit-test，验证输入框底衬透明、输入框本体有实底、工具卡片可点击、文本可选择、键盘事件可到达输入框、控制按钮位于宿主之上。
4. **启停与恢复回归：** 验证按钮和 `Alt+Shift+W` 都能开启及关闭，停用清理根层、控制层、样式和播放资源，停用状态可持久化并在重新注入后保持。
5. **启动目标回归：** 保留只读探针对主页面、Avatar 查询页、歧义目标和错误 WebSocket 端点的验证；新增页面适配不能放宽为接受任意 `app://` 页面。
6. **宿主复用回归：** 验证同一宿主请求处理可服务两个已核验页面，失败、关闭和锁释放仍只执行一次；不为成功路径复制现有失败路径测试。
7. **真实业务链路回归：** 在自动夹具中按“注入 → 选择素材 → 调整设置 → 切换页面 → 返回 → 停用 → 重新启用”的顺序执行一次完整流程，确认最终画面、配置和资源数量。

### 真实 Codex 端到端与视觉验收

在用户另选时间并明确允许操作真实候选实例后执行；修复阶段不得自行启动、关闭或重启正在使用的 Codex。

1. 从专用入口打开已有聊天，确认原账号、同一聊天和当前壁纸正常。
2. 连续至少 10 次在聊天与“变更”之间切换并录屏。逐次确认背景没有黑闪、默认渐变闪入、旧新画面交替或控制按钮消失。
3. 分别选择一张本地图片、一段本地视频、一个代表性 Scene 和一个离线 Web 预览，快速切换并等待最终稳定；确认最终只有一层背景和一个活动播放器。
4. 在输入框输入、选择文本、复制、滚动聊天并展开工具卡片；确认没有黑色大底衬，壁纸层不拦截操作。
5. 调整暗化、模糊、透明度和帧率，切换明暗主题，确认主聊天与变更页读取相同设置。
6. 使用按钮和 `Alt+Shift+W` 各执行一次停用与恢复；确认即时清理、状态保持和重新启用正常。
7. 正常退出后重开专用入口，确认上次素材和设置恢复。最终再从原入口打开，只读核对旧调试监听已关闭、原账号和同一聊天正常。
8. 保存不含聊天正文和账号信息的状态回执、截图或录屏摘要。视觉证据必须由交付者在交给用户前亲自检查。

### 测试审计门槛

- 每个测试必须在说明或提交信息中对应一个已复现问题或核心协议边界。
- 若一个测试只证明某个私有变量被赋值、某个内部函数被调用或某段 CSS 字符串存在，而相同行为已由计算样式、点击或页面状态覆盖，则删除该测试。
- 若现有大型静态背景测试中的断言仍分别防止不同用户可见回归，可以保留在同一浏览器生命周期内；只有在独立状态切换确实需要时才拆分。
- 修复完成时运行完整 Node 测试、PowerShell 启动器检查、Prettier 和 `git diff --check`。测试数量不是完成标准，真实业务路径覆盖和失败能否复现才是完成标准。

## Out of Scope

- 不修改受保护安装文件，不改变原 Codex 入口，不读取或迁移登录凭据与聊天正文。
- 不在本轮自行启动、关闭或重启用户正在使用的 Codex；真实冷启动和退出验收必须由用户安排。
